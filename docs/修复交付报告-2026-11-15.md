## 〇、一句话结论

插件不是"到处都坏"，而是**几处结构性问题**在传染：

1. **提示词有四份互相冲突的方案** —— 实际官方只有两套格式，缺的是一层模式路由器。
2. **Blender 预览从未真正渲出过角色** —— 相机默认值绕过了坐标换算，所有默认机位都是纯灰空帧。
3. **一批功能"看起来有、实际不生效"** —— 服化道、自定义风格、画布权限、模特出图、首尾帧预算。
4. **静态断言无法发现问题** —— 真机跑一遍又抓出 8 个 bug（见 [端到端报告](probes/e2e-2026-11-15/REPORT.md)）。

这三类都属于**静默失效**：不报错、不崩溃，只是结果不对。所以之前多轮"修复"很难发现它们。

## 二、Blender 建模 + 关键帧指引 H3

### 调研结论（`docs/probes/blender-previz-research/REPORT.md`）

**四通道本身不错，但"四个都渲、四个都送"是过度工程。**

| 通道 | 裁决 |
|---|---|
| **gray 灰模** | ✅ 完全正当，应是主角 |
| 彩色 preview | ✅ 正当，但只给人眼验收 |
| depth | ⚠️ 半正当（控制塔路线核心；Ref2VA 路线实测无增益） |
| pose | ⚠️ 半正当（渲人偶 ≠ 骨架，对 Pose 条件是无效输入） |
| **canny** | ❌ 最该砍（可从画面现算 + 阈值敏感） |

**社区标准交付是 1 段灰模视频 + N 张外观参考图**，不是四条通道。
实测：180° 环绕用 blockout 参考 **6/6** 成功；纯文字 **0/6** 稳定。

### 修复

**新增常规替代方案（推荐默认）：`blockout` 模式**

- Blender 渲一段灰模参考视频 → 填进镜头「参考视频」→ Ref2VA 的 `<Video N>`。
- **零额外模型**；`modeUsage()` 区分 control / reference / preview，`blenderStatus()` 下发 `recommended: 'blockout'` 与两条路线的说明。
- 渲染参数为参考视频优化：**平光（FLAT）**、无阴影、无 AO、无轮廓线、无高光、深色背景。
- 全部 6 个模式：`depth / pose / canny / gray / preview / blockout`。

**修掉两个实测发现的真 bug**（都是"渲出来是纯灰"级别）：

| bug | 现象 | 根因 |
|---|---|---|
| **相机默认值绕过坐标换算** | 所有没配 `camera3d` 的镜头，渲出**整片纯灰、逐帧相同** | `toBlenderVec(v, fallback)` 的 fallback 是原样返回的，却被传入了**镜头卡坐标** `DEFAULT_CAMERA3D`。相机落在 Blender Z-up 的 (0, 1.6, -4.2)，紧贴演员 |
| **blockout 单角色对比度** | 浅灰人站在浅灰地上，剪影消失（只剩一个白脑袋浮在地平线） | 单角色场景用了 `SINGLE` 灰 0.72，与地面同档 |

修完实测：366 帧渲染中 5/5 采样帧互不相同（动作生效），两个角色各自颜色清晰可读。

**顺带修正**：`buildSceneSpec` 的帧数从 `round(dur×24)`（5 秒 → **120 帧**，不在 `17k+5` 网格上）改为 `h3Length(dur)`（→ 124 帧）。参考视频比目标短 4 帧，尾部走位没人跟。
