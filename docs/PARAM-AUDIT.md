## 六、「45 秒一口气」到底能不能做

### 实测结论

| 路径 | 上限 | 可行性 |
|---|---|---|
| 原生节点 `length` | **3600 帧 = 150 秒** | 节点允许，但 tooltip 明写「trained range is ~124-362，**longer is untested**」 |
| 南风 V15 `时长秒` | **15 秒**（`min:1 max:15`） | 硬上限 |
| 12GB 显存 | 显存随时长**近似平方**增长 | 15s 1080p bf16 在 32GB 上都会溢出 |

**所以「45s 一口气」：技术上节点允许，但质量无保证且 12GB 显存绝无可能。**

### 正确做法：潜空间续写

群友说的「潜空间生成、不依赖首尾帧」就是 **Motion Context 续写**：
不用首帧/尾帧，而是把上一段**真实的 AV latent** 接到下一段开头。

```
45s = 3 段 × 15s（每段都在 124-362 帧训练区间内）
```

本插件已实现（`continuation.js` + `启用潜空间续写`），
关键参数：

| 参数 | 建议值 | 说明 |
|---|---|---|
| `context_length` | `22` | 复用上段末尾 22 帧（≈0.92s）作为上下文 |
| `audio_context_length` | `24` | 音频侧复用帧数 |
| `启用续写音频精修` | `true` | 消除接缝爆音 |

## 七、「the actual carried latent motion governs the current action」

这是南风续写 skill 里的**提示词写作规则**，原文在
`vendor/nanfeng/oneshot-continuation-skill/SKILL.md:14`：

> User intent specifies the desired action trajectory. Write later openings as
> continuation from **the actual carried motion**, not a guessed exact endpoint.

### 翻译

**从第 2 段开始，上一段真实生成的 latent 运动状态才是事实，你写的提示词只是意图。**

### 具体规则

| 该做 | 不该做 |
|---|---|
| 写「承接上段动作继续，推进到下一节拍」 | 写「第 2 段开头是角色举起左手到肩膀高度」 |
| 从**实际承接的运动**出发 | 猜一个精确的段尾姿势 |
| 图片只负责**身份/脸/发型/服装/外观/场景身份** | 用图片重置手位、视线、接触、道具状态、构图、动作相位 |

### 配套禁令

- 不得切、反打、瞬移构图、擦除、淡入淡出、新 take、姿势重置
- 不得在 trimmed overlap 窗口（`context_length` 那段）里引入新事件或新对白
- 相机必须连续变化，不能凭空发明速度或位置

**一句话**：**「怎么开始」由 latent 决定，「往哪去」由你的提示词决定。**

## 八、8.1 完整 Sigma 序列详解

群友给的：

```
1, 0.988235, 0.972973, 0.952381, 0.923077, 0.878049, 0.8, 0.631579, 0.42, 0.18, 0
```

### 我算过了

复刻 ComfyUI `simple` scheduler + `shift=12`：

```
simple/shift12  8步: 1.000000, 0.988235, 0.972973, 0.952381, 0.923077, 0.878049, 0.800000, 0.631579, 0
```

**前 8 个值与群友的序列 8/8 精确吻合**（误差 < 1e-5）。

### 所以它的结构是

```
[1, 0.988235, 0.972973, 0.952381, 0.923077, 0.878049, 0.8, 0.631579]
   ↑ simple/shift12 的 8 步标准网格（前 8 个点）
[0.42, 0.18]
   ↑ 尾部手工加密（在原网格的 0.6316 → 0 之间插了两档）
[0]
   ↑ 必须收尾于 0
```

### 它是干什么的

`H3完整Sigma序列`（D 组）—— **V8.1 潜空间放大二采**时**手动指定整条轨迹**。

| 项 | 值 |
|---|---|
| 值的个数 | 开二采时必须 = 一采步数 + 二采步数 + 1 |
| 默认 | `6 + 4 + 1 = 11` 个 ← **正好是群友给的 11 个** |
| 校验 | 必须**严格递减**，且**最后一个必须是 0**（`h3_generator.py:209-212`） |

### 为什么尾部要加密

低 sigma 阶段决定**细节与噪点纹理**。在 `0.6316 → 0.42 → 0.18 → 0` 之间插两档，
等于在"最后几笔"多给模型两次精修机会 —— 典型效果是**细节更实、暗部更干净**。

### 怎么用

1. 开 `启用H3潜空间放大二采`
2. `H3一采步数` = 6、`H3二采步数` = 4（合计 10 → 需要 11 个值）
3. `H3完整Sigma序列` 填这串
4. 留空则自动用 `simple/shift12` 的自动轨迹

> ⚠️ 别和 `手动西格玛`（F 组）搞混 —— 那个挂在 `sigma_requested=False` 的死分支下，
> 填了完全没反应。

## 九、打光：4:1 与 8:1 是什么

### 定义

**光比 = 主光 : 补光 = 亮面照度 : 暗面照度**。
光按「档」翻倍（1 档 = 2 倍），所以：

| 光比 | 相差档数 | 效果 | 典型用途 |
|---|---|---|---|
| **2:1** | 1 档 | 高调、柔和、明亮 | 日系写真、美妆、治愈系 |
| **3:1** | 1.7 档 | 经典人像，一侧柔和阴影 | 对话戏、人物特写 |
| **4:1** | **2 档** | 低调、戏剧化、明暗对比明显 | 悬疑、情绪戏、夜戏 |
| **8:1** | **3 档** | 极低调、黑色电影、明暗差 8 倍 | 母鸡卡剧场版、暗黑美学、演唱会顶光 |

参考：[Lighting ratio (Wikipedia)](https://en.wikipedia.org/wiki/Lighting_ratio)、
[UT Austin 影视灯光教程](https://cloud.wikis.utexas.edu/wiki/spaces/rtf318/pages/80022816/Lighting+ratios)

### 本插件怎么支持

南风 **221 个参数里没有任何打光参数** —— H3 是纯提示词驱动的，打光只能靠文字。
所以本轮新增 **`LIGHTING_PRESETS` 通道**（`host/bridge/prompt/h3-prompt.js`），
把摄影术语翻译成模型能执行的句子（光比 + 档数 + 阴影硬度 + 暗部保留度）：

| id | 名称 | 说明 |
|---|---|---|
| `none` | 不指定 | 跟随画风与参考图 |
| `high-key-2-1` | 2:1 高调柔光 | 亮部只比暗部亮一倍 |
| `classic-3-1` | 3:1 经典人像 | 一侧柔和阴影 |
| `dramatic-4-1` | **4:1 戏剧低调** | 明暗差 2 档，硬阴影边界 |
| `noir-8-1` | **8:1 极低调（黑色电影）** | 明暗差 3 档，大部分画面沉入近黑 |
| `rim-backlit` | 强边缘光（逆光勾边） | 逆光勾发丝，正面压暗 |
