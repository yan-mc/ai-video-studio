# v1.5.0 结构性修复记录

> 本文记录一次**结构性修复**（而不是逐条打补丁）的完整清单、根因分析与实测数据。
> 出发点是 2026-11-14 的全量校验报告：那次校验发现 4 个 P0、14 个 P1、若干 P2，
> 且其中多数是**同一类根因在不同模块的重复表现**。
>
> 因此本次修复的取舍是：**凡出现"多个 bug 复合"的模块，先重新设计再落地**，
> 而不是在原实现上叠 if。

---

## 0. 修复原则

三类根因贯穿了整个代码库，逐条修会不断复发：

| 根因 | 表现 | 本次的结构性对策 |
|---|---|---|
| **枚举多副本** | 动作名 57/59/27 三份；通道名 3 份；相机默认值 2 份 | 每类枚举**只留一个真源**，其余派生 |
| **编号即所有权** | ComfyUI 节点靠硬编码编号段避让，清理逻辑按编号白名单删 | 引入 `NodeGraph`，**按可达性剪枝**，不再需要"哪些编号该删" |
| **静默降级** | 32 个动作不生效、模型名被改写、路径越界被放过、探测失败当作成功 | 三态返回（成功/空/失败），失败一律可见 |

最终测试规模：`verify-all` 359 项 + `test-h3-graph` 40 项 + `test_actions` 6960 项
+ 前端 179 项 + `integration` 25 项，全绿。

## 1. 【P0】首帧链路必然失败 —— 模块重构

### 症状

任何「**无参考图 + 首帧/尾帧**」的镜头 100% 失败：

```
COMFY_HTTP_400: prompt_outputs_failed_validation
  node_errors: {"9": {"details": "'20'"}}
```

而这正是「Blender 渲首帧 → H3 出片」最自然的用法。

### 根因（复合）

`generator.js` 里三处逻辑耦合：

1. FL2VA 分支在节点 `20`/`21` 建首帧/尾帧的 `LoadImage`；
2. 收尾的清理循环用 `usedLoadImages = names.map((_, i) => 20 + i)`，
   `names` 只是**参考图**列表 → `20`/`21` 被判为"多余"；
3. `MiniMaxH3ImageToVideo.first_frame` 仍指向 `['20', 0]` →
   悬空连线，直到 ComfyUI 校验才暴露。

同类事故还有一次：`AddGuide` 从 `70` 开始编号，覆盖掉刚建好的 `70`/`71`
`LoadImage` → `"image, received_type(CONDITIONING)"`。

两者的共同点是**靠硬编码编号段约定来避让**。

### 修复

新增 `host/services/h3-graph.js`：

- `NodeGraph` 负责**唯一 ID 分配**（按用途分段，但不再承担正确性保证）
- `pruneUnreachable()`：从**输出节点**反向遍历，删掉一切不可达节点
- `validateLinks()`：提交前检查所有连线目标存在，否则抛
  `WORKFLOW_DANGLING_LINK`（而不是等 ComfyUI 报 `details: "'20'"`）

`runH3Local` 的节点装配改为全部走 `graph.set/alloc`，
收尾统一 `pruneUnreachable()` + `validateLinks()`。

> `_findOutputRoots()` 只认真实输出节点类型（`SaveVideo` 等）。
> 早期版本把"没有下游消费者"的节点也当根，结果 `20`/`21`/`63` 全被保留，
> 一个都剪不掉 —— 这个坑在 `h3-graph.js` 里写了注释。

### 验证

`tests/test-h3-graph.mjs`（40 项断言，5 个场景）：
仅首帧 / 仅尾帧 / 首+尾 / 纯文生 / 参考图+首帧。

**用旧代码跑这个测试会失败**（已验证）：
```
✗ [仅首帧（无参考图）] 存在悬空连线：[{"from":"9","to":"20","path":"9.inputs.first_frame"}]
✗ [首+尾帧（无参考图）] 存在悬空连线：[... "to":"20" ..., "to":"21" ...]
```

## 2. 【P0】动作系统三份枚举漂移 —— 单一真源

### 症状

59 个动作里有 **32 个**"前端能选、后端收下、Blender 渲出来人站着不动"，
且 `validation.warnings` 是空数组。实测 `point` 完全静止、
`wave` 在 24 帧里只有 72 个像素变化。

### 根因（三重）

| # | 问题 | 位置 |
|---|---|---|
| 1 | 前端手抄 57 项 | `RenderPage.tsx` 的 `ACTOR_ACTIONS` |
| 2 | 后端手抄 59 项 | `models.js` 的 `ACTIONS` |
| 3 | Python 只实现 27 个分支 | `render_shot.py` 的 `action_curve` |
| 4 | **旋转轴选错**：手臂沿 -Z 生长，绕 Z 只是自转 | wave/point/hug/cross-arms |
| 5 | **方向反了**：向上链 +X 是后仰不是前俯 | bow/pick-up/put-down |
| 6 | `EMOTION_AMP` 定义在 `apply_actor_actions` **之后**（NameError 炸弹） | `render_shot.py` |
| 7 | `durationFrames` 传成帧数当秒数；区间外关节瞬间归零 | `apply_actor_actions` |

### 修复

新增 **`host/blender/actions.py`**（纯 Python，不 import bpy）：

- 59 个动作全部实现，分 9 组；每个动作是 `_c_xxx(u, k, dur_s)`
- 提供**语义化关节构造器**：`arm_lift` / `elbow_bend` / `spine_bend` /
  `knee_bend` … —— 上层只表达"抬手 80 度"，不手写三元组
- `AXIS_CONTRACT` 把实测标定的轴语义写死

`models.js` 的 `actionCatalog()` **直接解析 actions.py** 取名字，
不再手抄；前端从 `GET /blender/actions/catalog` 渲染下拉。

`render_shot.py` 里：

- `action_curve` 退化成 3 行转发
- 新增 `_actor_timeline()` 统一处理起始/结束/时长（半开区间、最短 6 帧、区间外保持端点姿态）
- `EMOTION_AMP` 移到函数之前

### 轴语义标定数据（Blender 5.2.4 实测）

```
基准：肩 z=1.316，手 z=0.74

肩关节绕 Z ±45°   → 手 (0.198, 0, 0.74) → (0.198, 0, 0.74)   完全不动
肩关节绕 X ±45°   → 手 (0.198, ±0.407, 0.908)                前后摆
肩关节绕 Y -90°   → 手 (0.774, 0, 1.316)                     侧平举
肩关节绕 Y -140°  → 手 (0.568, 0, 1.757)                     过头
```

### 验证

`tests/test_actions.py`：**6960 项断言**，完全脱离 Blender 运行。

它断言的不只是"不报错"，而是：
- 每个 `animated` 动作的总关节变化 > 3°（低于此在 864×480 剪影里看不见）
- 手臂类动作在 **X/Y 轴**上必须有实质变化（Z 轴不计入 —— 那正是旧 bug）
- 前俯类动作的 `spine X` 必须 ≤ 0；后仰类必须 > 0
- 循环动作首尾闭合（`walk` 曾用 1.4 周期，首尾差 24.7°）
- 垃圾输入（`intensity='x'` / `NaN` / 未知动作名）不抛异常

**故意破坏验证**：把 `_c_wave` 改成 `return {}`，
`verify-all` 立即报 `FAIL 1` 并指出"wave 几乎不动 —— 白名单收了但曲线没实现"。

## 3. 【P0】相机默认值坐标写错 —— 单一真源

### 症状

只传 `camera3d: {fov: 45}`（缺 position）时，**渲出一张纯灰空画面**，
且没有任何报错。

### 根因

两层各写一套默认机位，其中一套是错的：

| 位置 | 默认 position | 经 `toBlenderVec` 后 | 结果 |
|---|---|---|---|
| `models.normalizeCamera3d` | `[0, -4.2, 1.6]` | `[0, -1.6, -4.2]` | **地下 4.2 米** |
| `blender-service.buildSceneSpec` | `[0, 1.6, -4.2]` | `[0, 4.2, 1.6]` | 正确 |

镜头卡约定是 `(x=左右, y=高度, z=深度)`，而 `[0,-4.2,1.6]` 里
`y=-4.2` 是负高度、`z=1.6` 是正向深度 —— 与约定直接矛盾。

### 修复

`models.js` 导出 **`DEFAULT_CAMERA3D`**（唯一真源），
`normalizeCamera3d` 与 `buildSceneSpec` 都从它取。

## 4. 【P0】Blender 帧号重命名崩溃 —— 幂等化

### 症状

同一个目录渲第二次时 Python 抛 `FileExistsError: WinError 183`，
但**PNG 序列已经完整落盘** → JS 侧按"产物存在"判定成功 →
用户看到成功，进程实际非零退出。

### 根因

```python
files = [f for f in os.listdir(out_dir) if f.startswith("f_")]  # 含上一轮 5 位文件
os.rename(f_0000.png -> f_00000.png)                            # 目标已存在 → 崩
```

### 修复

`pad_frame_numbers()`：只处理恰好 4 位数字的源文件；目标存在先删；
`os.replace` 代替 `os.rename`；单个失败不影响其余帧。
渲染前先清空目录，渲染后 `count_frames()` 只数 5 位帧号，
`<= 0` 时抛 `BLENDER_NO_FRAMES` —— 让失败**真的失败**。

## 5. 【P1】三个控制通道语义与训练分布不符

流程不崩，但控制力显著偏弱，属最难发现的缺陷。

| 通道 | 旧实现 | 训练侧事实 | 现在 |
|---|---|---|---|
| **canny** | 多做一次 `negate` → 白底黑线；阈值 0.06/0.18 | `cv2.Canny()` 原生 = **黑底白线**；ComfyUI 用 kornia，实测同样黑底白线；默认阈值 0.4/0.8 | 去掉 negate，阈值 0.20/0.45 |
| **depth** | `MapRange` 线性米制 | 逆深度 1/z 的 min-max（VACE / VideoX-Fun 都如此） | 节点链手算 `(1/z - 1/far)/(1/near - 1/far)` |
| **pose** | 纯白剪影 | **DWPose 彩色骨架**（模型卡原文 "Pose \| DWPose skeleton"） | COCO-18 limbSeq/colors 真骨架，肢体×0.6 |

### depth 实测

```
本机某镜：人物 3.5–3.8m，旧 near=2.34 far=7.67（按相机到注视点距离推算）
         → 主体只落在 93/255，与地面（固定 56）几乎糊在一起

新：near/far 按**场景几何包络**推算（compute_depth_range）
    near=3.44 far=14.7
    线性   → 144–162/255
    逆深度 → 73–88/255（暗剪影，梯度铺满全程）
```

地面也从"固定 0.22 灰"改为**走同一条逆深度链再乘 0.45** ——
既保留"越远越黑"的真实梯度，又保证人永远比地面亮。

### pose 骨架的三个坑（都已修）

1. `head`/`hand` 是**网格不是关节**，不在 `joints` 字典里 ——
   把它们写进 `need` 列表会让 `all(n in joints)` 恒假，整条骨架被跳过
2. 骨架必须在**每一帧**重新贴合关节。`apply_actor_actions` 结束时
   场景停在最后一帧，此时读世界坐标会把骨架冻结在动作终点
3. 人偶网格必须 `hide_render`，不能只涂黑 —— 否则会挡住画在
   它内部的骨架线段，只剩几段露在轮廓外的彩色碎片

另：COCO-18 是 **1=nose、2=neck**。早期按"1=neck"编号，
limbSeq 连出来的拓扑完全错位（一堆交叉线段，不成人形）。

## 6. 【P1】previz 产物无清理

### 症状

实测 5 次渲染在 `data/previz/blender/` 留下 **452 文件 / 74 MB**，
其中一次超时失败还留了 176 个半成品帧。
`extras.findOrphans` 只管 `data/assets/` 一层，previz 完全不在视野内。

### 修复

- `prunePrevizRuns(cfg, {keepRuns, maxBytes})`：保留最近 N 次 + 总字节上限，
  **永不删最新一次**
- `renderControl` 成功收尾时自动调用
- 失败时 `cleanupWorkDir()` 删掉半成品目录
- 新增 `GET /resources/previz`（占用情况）与 `POST /resources/previz/clean`（手动清理）

实测：`keepRuns:2, maxBytes:5MB` → 删 3 个目录、释放 34.5 MB，最新一次保留。

## 7. 【P1】路径安全 —— 统一到单一入口

### 症状

审计发现 **6 处**各写各的 `safeJoin` + `path.isAbsolute` 判断，
其中 **5 处漏掉绝对路径分支**。

实测可利用：
```
POST /assets/archive {"items":[{"path":"C:/Windows/.../hosts(复制为.json)"}]}
→ 200 {"ok":true,"saved":[{...,"rel":"assets/asset_xxx.json"}]}
→ GET /assets/item?id=asset_xxx  原样下载
```

### 修复

`security.js` 新增 **`resolveUserPath({root, input, allowSubdirs, mustExist})`** ——
所有接受路径的入口统一走它，绝对路径也必须落在 root 内（用 `realpath` 比较，
防 symlink 逃逸）。

已改造：`/assets/archive`、`post.*`、`comic` 导出的 `imageRel`、
`blender` 的 blend/asset、`blender-service.resolveInsideDataDir`。

顺带修掉：
- `openInBlender` 缺 `--disable-autoexec`（.blend 可内嵌自动执行脚本）
- `post.annotate` 的 `color`/`x`/`y`/`fontSize` 未校验就拼进 ffmpeg filtergraph
- `canvas-agent` 权限位由**请求体**决定（改为服务端权威），`canDelete` 默认 `true`→`false`
- `batch` 无限嵌套（50^N DoS），限深 1

## 9. 测试体系：从"字符串匹配"到"真的跑"

### 修复前

`verify-all.mjs` 报 **351 PASS / 0 FAIL**，但：

- 35 条 `B-Blender` 断言**全部**是 `svc.includes("'--factory-startup'")` 这类源码字符串匹配

所以 §1 的 P0、§3 的相机错误、§2 的 32 个空动作 —— **一条都测不出来**。

### 修复后

`B-Blender` 43 条，新增的都是**真的执行**：

| 断言 | 做法 |
|---|---|
| 动作库单测全过 | `spawnSync(python, ['tests/test_actions.py'])` |

同时新增两个独立测试文件：

- `tests/test-actions.*`（Python，6960 项）
- `tests/test-h3-graph.mjs`（Node，40 项，打桩 `runWorkflow` 不提交 ComfyUI）

两者都做过**反向验证**：故意引入旧 bug，测试必须失败。

## 10. 已知边界（本次未解决）

1. **Mixamo 导入模型渲染为空**。动作探测、骨架挂载、slot 设置都已验证正确
   （`Leg` 骨骼四元数逐帧在变），但导入后的包围盒归一化让模型跑到画面外。
   目前 pose 通道会 `POSE_SKELETON_FALLBACK` 退回剪影，depth/preview 仍是空白。
   建议在 `fit_imported` 里改用 `matrix_world` 的 8 角点重算包围盒。
2. **姿态通道依赖程序化人偶的关节**。导入模型没有 `joints`，
   只能退回剪影 —— 要真正支持需要从 Armature 的 pose bone 取点。
3. **H3 Fun ControlNet 的 depth 归一化没有官方文档**。
   逆深度结论来自训练侧代码（VideoX-Fun / VACE）交叉印证，属强推断。
4. **Blender 5.2 合成器 API 未使用**。文档 §2.3 描述的 `compositing_node_group`
   与本机实测不符（`bpy.types.Scene` 上没有该属性），当前实现走材质节点，
   不依赖合成器，反而更稳。
