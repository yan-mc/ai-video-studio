一、H3-Image 能力边界
════════════════════════════════════════════════════════════════════════════════

【必须知道的硬约束】

1. 采样步数固定 6，不可调
   checkpoint 的 safetensors 元数据写着 pdd_steps=6 + pdd_sigmas，
   ComfyUI 的 MiniMaxH3ImageModelSampling 把 sigma 索引线性映射到这条网格，
   final_layer 内置 6 套预测头、按当前 sigma 落在哪段取对应头。
   6 步 = 每步用一个头 = 训练态。
   4 步 = 一步跨 1.5 区间（分布外，画质掉）；12 步 = 一个区间用 2 步（浪费）。
   → 不要写 steps 参数。设了也只会被夹到 4–12 并被 /image/meta 标为 stepsOverridden。

2. guidance 固定 1.0，无 CFG
   BasicGuider 没有 guidance 输入，也没有 negative 分支。

3. 没有负面提示词
   采样器无 negative 通道。写"不要 XX"反而会把 XX 拉进画面。
   要排除东西就写"画面里只有…"，或用参考图约束。
   （例：不写 "no text"，改写 "the frame contains only the character and the set"）

4. 提示词上限 4096 字符，超长直接 400 拒绝（不静默截断）
   错误码 PROMPT_TOO_LONG。这是刻意设计：
   静默截断会让你写在末尾的"换成红色礼裙"被悄悄丢掉，出图没变化且无从排查。

5. 尺寸宽高必须是 32 的倍数
   节点按 height//16 取 latent、再按 patch_size=(1,2,2) 打块。
   非 32 倍数会被 pad_to_patch_size 补边，产物尺寸与请求不符
   （实测：请求 2368×1776 产出 2368×1792）。
   边长至少 256。自定义宽高必须成对给出。

6. 面积上限默认 4.3 MP（可配 imageMaxMP）
   2048² = 4.19MP 是 12GB 卡实测能跑的上限。4096² 是 16.8MP，必 OOM。
   超过上限报 IMAGE_TOO_LARGE。

7. 参考图上限 16 张（不是视频的 9 张）
   注意这是两套不同上限：
     · 视频（南风 V15）：图片1..图片9，共 9 个槽位
     · 图像（H3-Image）：images.image_1..image_N，AUTOGROW 最多 100，实用上限 16

8. 批量 count 1–4，是拆成 N 个独立任务
   H3-Image 的 DiT 硬性拒绝 batch>1
   （comfy/ldm/minimax/model.py 里 raise ValueError("MiniMax H3 supports batch size 1")）。
   所以 count=3 会返回 3 个 jobId，种子按 seed+1、+2 递增。

9. auto 尺寸的真实行为
   · 无参考图 → 2048×2048
   · 有参考图 → 用第 1 张缩放后的尺寸（短边约 1024–2048）
   → 想锁定尺寸请显式给 sizeId 或 width/height，不要依赖 auto
   返回的 meta.sizeResolvedFrom 会告诉你这个数从哪来：
     'explicit' 显式指定 / 'ref' 继承参考图 / 'default' 默认 2048

10. 单张耗时参考（本机 RTX 4080 Laptop 12GB + w4a8）
    1024² 无 LoRA          约 66–80 秒
    1024² 1 条 LoRA(bypass) 约 88–110 秒
    2048² 无 LoRA          约 148 秒
    LoRA 首次加载有额外冷启动（可能到 200 秒+），之后走缓存

二、Agent 工具 studio_image（DSH 内首选）
════════════════════════════════════════════════════════════════════════════════

在 DSH 对话里直接用，不需要 token，插件自动鉴权。

动作：meta / lora / generate

────────────────────────────────────────────────────────────────────────────
2.1  action='meta'  —— 出图前先查这个
────────────────────────────────────────────────────────────────────────────
调用：studio_image { action: 'meta' }

返回关键字段：
  effective.steps            真实生效步数（通常 6）
  effective.declaredSteps    声明值
  effective.stepsOverridden  配置是否覆盖了默认
  effective.maxMP            面积上限
  effective.promptMaxChars   提示词上限（4096）
  effective.maxRefImages     参考图上限（16）
  effective.maxBatch         批量上限（4）
  effective.maxLoras         LoRA 上限（6）
  effective.samplingLocked   true = 采样参数不可调
  sizes[]                    尺寸表（id / 名称 / 宽高 / MP）
  status.ready               模型是否就绪
  loraCategories[]           6 个 LoRA 分类
  loraRoot                   'h3img'（图像 LoRA 的目录前缀）

────────────────────────────────────────────────────────────────────────────
2.2  action='lora'  —— 看装了哪些图像 LoRA
────────────────────────────────────────────────────────────────────────────
调用：studio_image { action: 'lora' }

返回：
  probed        true=探测成功；false=ComfyUI 不可达（**不代表没装**）
  items[]       每项含 name / base / categoryId / categoryLabel / strength / why
  total         数量
  root          'h3img'

⚠️ 只有放在 models/loras/h3img/ 下的文件才会出现在这里。
   视频 LoRA（00_turbo/、30_style/ 等）不会混进来。

────────────────────────────────────────────────────────────────────────────
2.3  action='generate'  —— 出图
────────────────────────────────────────────────────────────────────────────
参数（除 prompt 外全部可选）：

  prompt        string   必填。≤4096 字符
  refImages     array    参考图（rel 路径或 dataURL），≤16 张
                         ⚠️ 第 1 张 = 被编辑的原图，决定输出画布与编辑目标
  sizeId        string   尺寸 id，见 meta.sizes。默认 auto
  width/height  number   自定义尺寸，必须成对、32 倍数、≥256。覆盖 sizeId
  seed          number   不给随机。count>1 时其余样本 seed+1、+2…
  count         number   1–4，拆成 N 个独立任务
  loras         array    [{name, strength}]，≤6 条
  projectId     string   可选，挂到项目下

返回：
  jobId / jobIds[]   任务号（count>1 时多个）
  batchId            批次号
  count              实际任务数
  mode               't2i' 文生图 / 'edit' 参考图编辑
  refCount           实际用上的参考图数
  loraStack          实际生效的 LoRA 与求解后强度
  seed               实际种子（可能被随机）
  warnings[]         必须读！包含参考图丢失、LoRA 被替换/衰减/剔除等原因

典型调用：

  // 1) 纯文生图
  studio_image {
    action: 'generate',
    prompt: 'A silver-haired anime girl on a rehearsal stage, deep blue gown, warm toplight, cinematic',
    width: 1024, height: 1024,
    seed: 7777
  }

  // 2) 参考图编辑（改背景，保留角色）
  studio_image {
    action: 'generate',
    prompt: 'Edit <Picture 1>: change the background to a warm sunset sky, keep the subject and pose unchanged.',
    refImages: ['assets/角色立绘.png'],
    sizeId: 'auto'
  }

  // 3) 带 LoRA
  studio_image {
    action: 'generate',
    prompt: '@ningen_mame, a girl reading in a cafe, soft window light',
    width: 1024, height: 1024,
    loras: [{ name: 'h3img\\30_style\\ningen_mame_late_h3_v2.safetensors', strength: 0.9 }]
  }

  // 4) 批量抽卡（同 prompt，4 个种子）
  studio_image {
    action: 'generate',
    prompt: '...',
    count: 4,
    seed: 1000
  }

────────────────────────────────────────────────────────────────────────────
2.4  查进度
────────────────────────────────────────────────────────────────────────────
用 studio_jobs { action: 'list' } 或 { action: 'get', jobId: '...' }。

进度字段在 job.params.progress：
  { pct: 35, note: 'GPU 生成中（1 条 LoRA）', queue: {...} }
三态：排队（15%）→ GPU 生成中（35%）→ 正在取回产物（85%）

产物位置：
  data/outputs/<jobId>.png      临时区
  data/assets/asset_*.png       自动归档进素材库（推荐用这个）
job.outputs[0] 里同时有 rel / archivedRel / assetId

三、REST 路由（外部脚本用）
════════════════════════════════════════════════════════════════════════════════

基础：http://127.0.0.1:<DSH端口>/jiuzhang/api
当前端口见 DSH 运行时（本次为 3641，重启会变）

鉴权：
  GET /token 免 token，返回 { token, origin }
  写方法（POST/PUT/PATCH/DELETE）必须带 X-JZ-Token 头
  跨源请求会被拒（同源校验）

────────────────────────────────────────────────────────────────────────────
3.1  图像相关（本文重点）
────────────────────────────────────────────────────────────────────────────

GET  /image/meta
     图像能力元信息。返回 models / vae / clip / sampling /
     effective（真实生效值）/ sizes / status / loraCategories。

GET  /image/lora/catalog
     图像 LoRA 目录。只列 models/loras/h3img/ 下的文件。
     返回 probed / items[] / categories / total / hint。

POST /image/lora/solve
     图像 LoRA 约束求解。
     入参：{ items: [{name, strength}], hasRefImages?: bool, maxSlots?: number }
     返回：{ accepted[], rejected[], replaced[], degraded[], totalStrength, warnings[] }
     规则：画风/角色单选（后来替换先来）、多挂类按 stackDecay 递减、
           总强度>1.5 警告 / >1.8 剔除最弱、
           画风×角色 与 角色×参考图 两条硬冲突告警。

POST /image/generate
     出图。入参见 2.3。
     错误码：
       400 PROMPT_REQUIRED      提示词为空
       400 PROMPT_TOO_LONG      超 4096 字符
       400 SIZE_INCOMPLETE      宽高只给了一个
       400 SIZE_TOO_SMALL       边长 <256
       400 IMAGE_TOO_LARGE      面积超 imageMaxMP
       400 IMAGE_TOO_MANY_REFS  参考图超 16 张
       400 REF_IMAGE_UNRESOLVED 参考图一张都解析不到
       409 IMAGE_MODEL_MISSING  模型文件缺失
       409 IMAGE_VRAM_LOW       空闲显存低于阈值
       500 WORKFLOW_MISSING     缺 data/workflows/h3-image.json

GET  /image/progress?ids=job_a,job_b
     轻量进度（前端 1.5s 轮询用）。只回 status / progress / 产物 rel，
     比 /jobs/:id 小一个数量级。
     返回：{ ok, jobs: [{ id, status, error, progress:{pct,note}, params:{seed,batchIndex,batchSize}, outputs[]{rel,archivedRel,assetId,bytes} }] }

  画风 @0.8 + Artistic @0.9                        = 1.7  ✓ 画风 + 解剖精修
  画风 @0.8 + Doggy_A_Pov_1 @0.75                  = 1.55 ✓ 画风 + 动作
  画风 @0.7 + Artistic @0.85 + Doggy_A_Pov_1 @0.7  = 2.25 ✗ 超线，会出坏图

────────────────────────────────────────────────────────────────────────────
4.1  ningenmame style（にんげんまめ）
────────────────────────────────────────────────────────────────────────────

文件：h3img\30_style\ningen_mame_late_h3_v2.safetensors
来源：https://civitai.com/models/3010902
作者训练说明：只用画师后期作品训练，早期作品未使用

触发词（必须写）：@ningen_mame
推荐强度：0.8 – 1.2
推荐步数：6

⚠️ 作者明确警告：
   "This model will reproduce bad image when the total lora strength
    (including other loras) is above 2.0, improve steps from 6 to 12
    will help solve the problem"
   → 总强度（含其它 LoRA）不要超过 2.0
   → 真出坏图时，把 steps 提到 12 可缓解
     （但本插件锁 6 步；要试 12 步需临时改配置 imageSteps=12，
       改完 /image/meta 会显示 stepsOverridden=true）

风格特征（实测）：
  · 线条细腻、边缘柔和
  · 平涂为主 + 少量柔和渐变（不是硬 cel-shading）
  · 肤色偏柔、五官收敛、表情内敛
  · 整体"绘师手绘感"强，写实度低于默认 H3-Image

用法示例：
  prompt: '@ningen_mame, a girl reading by the window, soft afternoon light, warm tones'

  1. studio_image { action: 'meta' }        确认 ready=true，看上限
  2. （可选）studio_image { action: 'lora' } 看有哪些 LoRA
  3. studio_image { action: 'generate', ... }
  4. studio_jobs { action: 'get', jobId } 或看 job.params.progress
  5. 产物用 outputs[0].archivedRel（素材库路径，长期有效）

要改一张已有图：
  1. 确认源图在素材库里有 rel（GET /assets）
  2. studio_image {
       action: 'generate',
       prompt: 'Edit <Picture 1>: 要改什么。keep ... unchanged.',
       refImages: [rel]        ← 第 1 张 = 被编辑的原图
     }
  3. 想锁尺寸就显式给 width/height；不然 auto 会继承源图

要套 Sweet Butter Cookie 风格：
  1. 源图**要带真实场景背景**（否则背景会变纯黑）
  2. prompt 直接用那句触发词整句
  3. refImages: [源图rel]
  4. loras: [{ name: 'h3img\\30_style\\SweetButterCookie_H3edit_v1.safetensors', strength: 1.0 }]

要套 ningenmame 风格：
  1. prompt 开头写 '@ningen_mame,'
  2. loras: [{ name: 'h3img\\30_style\\ningen_mame_late_h3_v2.safetensors', strength: 0.9 }]
  3. 总强度别超 2.0

要套 Flat Style：
  1. prompt 可选加 'flat anime color, bold clean flat colors, minimal shading,'
  2. loras: [{ name: 'h3img\\30_style\\Minimax Image - Flat Style.safetensors', strength: 0.9 }]

要修下体解剖（★推荐，可叠在画风之上）：
  1. prompt 写自然描述，不用触发词：
     'artistic nude figure study, smooth hairless mons pubis,
      symmetrical softly rounded contours, neat closed vertical labial cleft'
  2. loras: [{ name: 'h3img\\32_quality\\minimax_h3_artistic_solo_anatomy_v0_2.safetensors',
               strength: 0.9 }]
  3. 想同时要画风：再加一条 30_style 的（总强度控制在 2.0 以内）
     例：画风 0.8 + Artistic 0.9 = 1.7 ✓

关于 3D Animations NSFW Helper：
  → **不要用**。它是视频 LoRA，实测会破坏画面（见 4.5）。
    真要试就把强度压到 0.5 以下，并用参考图锁角色，且预期会变形。

【第一轮：三个画风 LoRA】
参数：1024×1024，seed 7777，步数 6，prompt 统一为
      "A silver-haired anime girl standing in a rehearsal hall,
       deep blue gown, warm toplight, dark curtain background, cinematic composition"

  00-基线-无LoRA            80.3s   标准 H3-Image 风格（柔和渐变、写实动画感）
  01-ningenmame @0.9       233.7s   线条细腻、平涂+柔渐变、绘师感（首次含冷启动）
  02-FlatStyle @0.9        193.5s   硬 cel-shading、大色块、无渐变（首次含冷启动）
  03-SweetButterCookie     246.3s   极简粉彩、细节平化（首次含冷启动）
    @1.0 + 参考图(白底立绘)          背景变纯黑 —— 源图背景是白色导致

Sweet Butter Cookie 背景复验（说明黑底原因）：
  A. strength 0.7 + 白底立绘    110.6s   仍纯黑 → 不是强度问题
  B. strength 1.0 + auto 尺寸    95.4s   仍纯黑 → 不是尺寸问题
  C. strength 1.0 + 有场景源图   ~100s   **背景完整保留**（舞台/幕布/木地板全留）
  → 结论：黑底源于"源图是纯白空背景"，非 LoRA 缺陷。
     要保留背景，源图必须有真实场景。

    判断 LoRA 是否生效**不能只看耗时**，必须做同 seed 像素对照。
