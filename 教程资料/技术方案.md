- Host 静态服务只指向 `app-dist`

## 四、画布设计（React Flow）

### 4.1 数据模型

```ts
interface CanvasDoc {
  version: 1;
  projectId: string;
  nodes: CanvasNode[];
  edges: CanvasEdge[];
  viewport: { x: number; y: number; zoom: number };
}

interface CanvasNode {
  id: string;
  type: string;              // 'aiImage' | 'aiVideo' | 'textNote' | …
  position: { x: number; y: number };
  data: Record<string, unknown>;   // 节点自己的参数
  parentId?: string;         // 分组
}

interface CanvasEdge {
  id: string;
  source: string;
  sourceHandle?: string;
  target: string;
  targetHandle?: string;
}
```

## 五、四个图像工具（已确认范围）

| 工具 | 后端实现 | 前端交互 |
|---|---|---|
| **裁剪** | 用 ffmpeg `crop` | 画框选区 + 比例预设（自由/1:1/16:9/9:16/4:3/3:4） |
| **切割分镜** | ffmpeg `crop` 循环，或 sharp | 行列数输入 + 预览网格 → 出多个结果节点 |
| **标注** | sharp 合成（或 Canvas 前端导出 PNG） | 画笔/形状/文字 + 配色/线宽 |
| **抠图** | 需模型；先用色键/简单阈值，或接 H3-Image 编辑 | 一键处理 |

**共同规则**：产物一律**新节点**，原图不覆盖。

**说明**：`sharp` 需要 Node 原生模块。若不想引入，裁剪/切割可用 ffmpeg（现有依赖），标注用前端 Canvas 导出。

## 八、技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| React Flow 学习曲线 | 交互细节多 | 先用官方示例跑通，再定制 |
| 构建链引入 | 项目从「无构建」变「要构建」 | **产物进仓库**，用户不需要构建 |
| 26 种节点工作量大 | 每个都要 UI + 后端 | S3 分批做，先 5 个核心 |
| 图像模型缺失 | 抠图/高清/扩图依赖模型 | 4 个工具里抠图最受限，先做简单版 |
| DSH 端口不固定 | 静态服务路径含端口 | 用相对路径，前端自动适配 |
| 插件重载后 SPA 缓存 | 用户看到旧版 | 资源文件名带 hash（Vite 默认） |
