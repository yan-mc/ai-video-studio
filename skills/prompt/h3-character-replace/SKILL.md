# 人物替换专属规范 v1.1

> 核心场景：视频换人、角色替换（Video Editing / identity swap）。
>
> 底层逻辑：H3 的注意力预算有限。替换任务的核心是「**保动作、换皮囊**」——
> 把最强的注意力放在「身份映射」和「动作复刻」上，
> 不要让它分心去重绘背景或生成音频。

---

## 一、四条铁律

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **音频必须从素材层剥掉** | 不是"提示词不写 `<Audio N>`"就够了。H3 Ref2VA 会把参考视频**自带的音轨**自动作为 `<Audio j>` 送进条件 —— 源视频带声音时，你一个音频标签都不写，输出音轨照样被原声污染。**必须先剥音轨**（见 §五·1） |
| 2 | **不写 `overall_soundscape` / `non_diegetic_music` 字段** | 纯视觉任务不需要这两位，写了会分走注意力 |
| 3 | **不写长篇光影 / 环境描述** | 光影、构图、场景 100% 继承 `<Video 1>`；用文字重写会导致背景闪烁重绘 |
| 4 | **不写否定式 `Forbidden` 列表** | 本地 CFG 固定 1.0、采样器没有 negative 分支，正文里的"不要 X"反而会把 X 拉进画面。把防御性约束融进**正面描述** |

> 这四条与 `jiuzhang-prompt-spec` 的常规六字段规范**互斥**：
> 常规规范要求六个字段齐全（含两个声音字段），替换任务**只有前三段**。
> 判定依据是任务类型，不是格式偏好。同一份提示词不能同时满足两者。

---

## 二、标准四段式模板

```text
第一句（总结全片 · 最强注意力）：
将参考视频1视频中的[原角色A特征]替换成参考图1[目标角色B特征]。完全复刻参考视频1内动作。

第二句（锁定身份 · 建立映射）：
<Subject 1> 是 <Picture 1> 中的[目标角色B]，替换原视频中的[原角色A]。
<Video 1> 是源视频，保留其完整动作、运镜和剪辑节奏。

第三句（详细分镜 · 按时间轴拆解动作）：
[Shot 1] 起始帧：[景别]。[Subject 1] [动作描述]...
[Shot 2] At 00:02.500，[景别]。[Subject 1] [动作描述]...

第四句（强化约束 · 防漂移）：
全程保持 <Subject 1> 的身份和外观与 <Picture 1> 完全一致。完全复刻 <Video 1> 内动作，不添加新角色。
```

**四句的分工**：

| 句 | 作用 | 为什么放在这个位置 |
|---|---|---|
| 第 1 句 | 全片最高优先级指令 | 放最前，权重最高；同时给出「原角色特征」与「目标角色特征」，建立映射 |
| 第 2 句 | 建立 `<Subject N>` / `<Video N>` 绑定 | 官方要求引用标签在使用前先定义一次 |
| 第 3 句 | 时间轴动作拆解 | 让模型知道每一秒该复刻什么，而不是自由发挥 |
| 第 4 句 | 防漂移 | 结尾再压一次身份一致性，抵消长提示词中的注意力衰减 |

## 三、实战示例：把源视频人物替换为「睦子」

背景：源视频 `<Video 1>` 是 5 秒、女性在走廊回头奔跑的镜头（**已剥音轨**）。
目标：把里的金发女人换成「睦子」（`<Picture 1>`）。

```text
将参考视频1视频中的金发女人替换成参考图1中的睦子（浅绿长发、左侧发卡、琥珀瞳）。完全复刻参考视频1内动作。

<Subject 1> 是 <Picture 1> 中的睦子，替换原视频中的金发女人。
<Video 1> 是源视频，保留其完整动作、运镜和剪辑节奏。

[Shot 1] 起始帧：中景。原金发女人（现替换为 <Subject 1>）站在走廊尽头，身体背对镜头，随后突然转头，露出她的侧脸。
[Shot 2] At 00:02.000，特写。<Subject 1> 的面部正面朝向镜头，她快速眨眼，发丝随着转头动作甩动，左侧发卡清晰可见。
[Shot 3] At 00:03.500，中景。<Subject 1> 转身向画面右侧奔跑，镜头跟随她平移，衣摆随奔跑动作自然飘动。

全程保持 <Subject 1> 的身份和外观与 <Picture 1> 完全一致。完全复刻 <Video 1> 内动作，不添加新角色。
```

## 四、自查清单

- ☐ 源视频**已经剥掉音轨**了吗？（§五·1，最容易被漏掉的一条）
- ☐ 第一句是否同时包含「原角色特征」和「目标角色特征」？
- ☐ 是否只用了 `<Subject 1>` 和 `<Video 1>` 两个核心素材标签？
- ☐ 是否彻底没有 `<Audio N>` 与两个声音字段？
- ☐ 每个 `[Shot N]` 是否都在强调「复刻原动作 / 原运镜」？
- ☐ 全文有没有独立的"不要 X"句子？（有就改成正面描述）

## 五、在本插件里怎么落地

### 5.1 提交参数（最容易做错的一步）

| 项 | 值 | 说明 |
|---|---|---|
| 模式 | `ref2va` | 替换必须有参考视频；`i2va`/`fl2va` 会直接拒绝视频参考 |
| 图片槽 | `图片1` = 目标角色 | 对应 `<Picture 1>` |
| 视频槽 | `视频1` = 源视频（**已剥音轨**） | 对应 `<Video 1>` |
| 音频槽 | 全部留空 | 铁律 1、2 |
| 提示词 | 上面四段式全文 | 直接粘进 `提示词` 字段（>200 字符时编译器会原样保留，不再改写） |

**先剥音轨再提交**：

```text
studio_post {op:'stripAudio', input:'assets/source.mp4'}
  → 产出 assets/<新文件>.mp4（视频流原样复制，无重编码、无画质损失）
  → 用产出的 rel 填进 shot.refs.videos
```

命令行等价物：`POST /jiuzhang/api/post/stripAudio {"input":"assets/source.mp4"}`。

> **为什么不能只靠提示词**：ComfyUI 的 `MiniMaxH3ReferenceToVideo` 里
> `if soundtrack is not None:` 就 append 一个 audio token（源码
> `comfy_extras/nodes_minimax_h3.py:352`），并且南风的
> `build_native_prompt` 按"这段视频有没有音轨"决定 `<Audio j>` 的分配。
> 也就是说**音频编号是素材驱动的，不是提示词驱动的**。
> 保持音频槽留空 ≠ 没有音频；源视频的音轨会自动占号。

### 5.2 与续写的关系

替换任务**通常不需要续写**（源视频本身就是连续动作）。
若源视频很长必须分段替换：每段都用**同一个目标角色参考图**，否则不同段会漂成两个人。

### 5.3 与光影参数的关系

`lightingId` 设为 `none`（跟随源视频）。手动指定光比与铁律 3 冲突 ——
光必须 100% 继承源视频，用文字重写会导致背景闪烁重绘。

### 5.4 常见失败与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| **输出里有原视频的声音 / 音效** | 源视频自带音轨，被 Ref2VA 自动接成 `<Audio 1>` | **先用 `stripAudio` 剥音轨**（§5.1）——这一条最常被漏 |
| 背景闪烁 / 重绘 | 提示词里写了光影或场景描述 | 删掉所有光影/环境句，只留动作 |
| 出现字幕或 UI | 没加压制行 | 在分镜前补一行 `Text suppression: NO subtitles, ...`（见 `jiuzhang-prompt-spec` §7.5 的三处合法位置） |
| 角色身份漂移 | 第 4 句缺失或太靠后 | 第 1 句和第 4 句都要带目标角色特征 |
| 动作没复刻 | 分镜里没写「复刻原动作」 | 每个 `[Shot N]` 都加一句复刻声明 |
| 生成了嘴型 / 说话动作 | 写了 `<Audio N>`，或源视频里人物原本在说话 | 删标签；若原片确实在说话，在第 3 句写明「保持原有口型节奏，不新增对白」 |
| 报 `NANFENG_CONSTRAINT` | 镜头卡模式不是 `ref2va` | 把模式切到 `ref2va`，见 5.1 |
