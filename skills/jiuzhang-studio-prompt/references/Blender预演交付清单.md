# Blender 预演 → AI 视频：镜头级交付清单

> 目标：让 Blender 预演真正变成模型能吃的**结构信息**，而不是一张参考图。
>
> 两条路线，**默认走第一条**：
>
> | 路线 | 交付物 | 额外模型 | 单镜耗时 | 何时用 |
> |---|---|---|---|---|
> | **① 灰模参考视频（推荐）** | `blockout.mp4` | 无 | 基准 | 几乎所有镜头 |
> | ② 控制塔（ControlNet） | `depth.mp4` / `pose.mp4` | 4.22 GB | +83% | 必须硬锁结构时 |
>
> 实测依据：180° 环绕用 blockout 参考 **6/6** 成功；纯文字 **0/6** 稳定。
> 控制塔的通道叠加会互相打架（skip 相加 → 过饱和），建议配比 depth 0.3 + pose 0.7。

---

## 一、预演前

- [ ] 确认目标模型：H3 本地（ComfyUI）/ H3 API / Wan 2.x / 其他
- [ ] 确认目标规格：**H3 最短 5.17 秒（124 帧）**，不是 4 秒；最长 15.08 秒（362 帧）
- [ ] 分辨率：H3 原生 **1344×768**，宽高必须 **32 倍数**
- [ ] 角色/场景/道具用**纯色白模**（避免贴图被当成平面图）
- [ ] 机位、景别、遮挡关系、动作节奏按最终分镜摆好
- [ ] **fps = 24**（必须等于目标模型帧率；Wan 是 16）
- [ ] 多角色上**饱和身份色**并记录色号（全灰 playblast 会丢失身份区分，实测多人左右会互换）
- [ ] 至少放一个**不对称地标**（否则"环绕 180°"和"原地不动"在画面上一样）

---

## 二、要导出的文件

### 路线① 灰模参考视频（默认）

| 文件 | 规格 | 用途 |
|---|---|---|
| `blockout.mp4` | 24fps、帧数 = 目标帧数、32 倍数宽高、平光无阴影、多角色带身份色 | **填进镜头「参考视频」** → Ref2VA 的 `<Video 1>` |
| `char_*.png` | 2–4 张独立高清图（短边 2048），正/四分三/侧/服装细节 | Ref2VA 的 `<Picture N>`；**不要 3×3 网格** |
| `scene_*.png` | 与分镜一致的场景参考 | 场景/风格参考 |
| `voice_*.wav` | 2–15s、32kHz、单一声源 | `<Audio N>` 音色参考 |

### 路线② 控制塔（仅在需要硬锁结构时）

| 文件 | 规格 | 用途 |
|---|---|---|
| `depth.mp4` | 24fps、**16bit 固定 near/far**（不是逐帧归一）、近白远黑 | **填进镜头「控制视频」** → Fun ControlNet Depth |
| `pose.mp4` | 24fps、**黑底白线的骨架**（不是人偶剪影） | Fun ControlNet Pose |
| `gray.mp4` | 24fps、灰模整体 | Fun ControlNet Gray（光影布局） |
| ~~`canny.mp4`~~ | — | **不建议**：边缘可从任意画面现算，阈值敏感，无公开 A/B 支持 |

### 两种路线都可能需要

| 文件 | 规格 | 用途 |
|---|---|---|
| `frame_first.png` | 目标画幅，干净渲染 | FL2VA/I2VA 首帧（注意与 Ref2VA 互斥） |
| `frame_last.png` | 同上，留安全边 | FL2VA 尾帧 |
| `camera.json` | 机位/焦距/关键帧/时间 | 记录 + 转写运镜提示词 |

## 三、检查（上传前）

- [ ] **帧数在 `17k+5` 网格上**（124 / 141 / … / 362）。参考视频渲成 120 帧会被裁到 107 帧，尾部走位没人跟 —— 上面表里的 `blockout.mp4` 必须渲成**目标帧数**
- [ ] 控制/参考视频帧率 = 24fps，时长与目标一致
- [ ] 首帧已按目标画幅裁剪（H3 的 `first_frame` 直接缩放**不保比例**，off-aspect 会拉伸；`last_frame` 居中裁剪）
- [ ] 素材数量：图 ≤9、视频 ≤3、音频 ≤3、**合计 ≤12**；每段视频/音频 2–15s，各自总时长 ≤15s
- [ ] **参考音频不是唯一参考**（官方要求至少 1 图或 1 视频；本地节点不拦，但音色会漂）
- [ ] **模式唯一**：首尾帧模式与 Ref2VA 模式**不可混用**
- [ ] 提示词按官方结构（基础三字段 / Ref2VA 六段），标签与素材一一对应
- [ ] **提示词里的人数、主要道具、机位方向，必须与参考/控制视频一致** —— 否则前几秒会被提示词抢走
- [ ] 记录：Blender 版本、场景文件、机位、渲染参数、模型文件、LoRA、步数、seed、有效时长

---

## 四、生成后 QC

- [ ] 首帧/尾帧与预演一致性（构图、景别、主体位置）
- [ ] 参考/控制视频与输出的偏差（抽帧对比，记录偏差程度）
- [ ] **灰模泄漏检查**：输出里有没有出现白模/胶囊体/线框
- [ ] 人数、左右顺序、遮挡关系是否保住
- [ ] 口型与台词时长是否对得上（按 4–5 字/秒）
- [ ] 音频是否 32kHz 立体声、无静音

---

## 五、常见失败与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 输出是灰模/白模 | 参考视频直接渲成片风格了，模型整段照抄 | 提示词加"deliver a fully rendered frame in the target style"；参考视频保持平光 |
| 前几秒不跟随 | 提示词与参考视频内容冲突（人数/道具/机位不一致） | 三样对齐；控制强度往 1.5 提 |
| 人物越走越大/纵深漂 | 只用 depth，VAE 16× 压缩后纵深信息不足 | 加 pose；或配比 depth 0.3 + pose 0.7 |
| 多人左右互换 | 全灰 playblast 丢失身份 | 上身份色，提示词引用色号 |
| 最后一下动作失真 | 参考视频比目标短（120 vs 124 帧） | 帧数渲成目标帧数 |
| 片子发白/人物糊 | 通道叠加过饱和 | 降配比；`end_percent` 收到 ~0.6 |
| 口型崩坏 | 台词字数超过镜头时长 | 按 4–5 字/秒反推，或加长镜头 |
| 整段风格被参考视频带跑 | H3 参考视频抓力过强 | 社区有 `MiniMaxH3ReferenceVideoFade` patch 可松 |
