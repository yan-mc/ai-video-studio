## 〇、一句话结论

**工程骨架与工具层已经做完（≈88%），但"能真正产出 AI 视频"这条主链路是断的：预演产生的首尾帧进不了生成后端，生成后端也从未真实跑通过一次。当前唯一能输出的视频是纯色占位片。**

这不是"差一点环境"的问题，而是**三处结构性断点**（§三）。在补齐它们之前，项目的实际可用度远低于代码完成度给人的印象。

## 一、项目是什么

一个**自用**的本地 AI 视频制作工具，形态是 **DSH Web 插件**。设计意图：

1. **DSH 主面板即应用界面** —— 不另做独立应用，插件侧栏加一个入口，主面板是「预演导演台式」工作台；
2. **本地为主、云端兜底** —— MiniMax H3 本地（ComfyUI）优先，可切 Seedance 云端；未接入时用 mock 占位保证链路可测；
3. **3D 预演先行** —— 先在灰模里摆演员/调机位/排动作，导出首帧/尾帧/控制视频，再交给视频模型做参考生成（绕过"提示词说不清"的核心路径）；
4. **资产全外置** —— 3D 模型/动作/道具/schema 做成可挂载资产包，插件本体零资产；
5. **软件端先行** —— 真实 API 未就绪前把工程/UI/适配器全部做完。

## 三、三个致命断点（本轮亲测核实）

### 🔴 断点 1：预演 → 生成 完全断链

这是最严重的问题。预演花了大力气做出 85%，但产物**没有一条路径进入生成后端**：

| 环节 | 实测证据 |
|---|---|
| `attachPrevizToShot()` 写入字段 | 只有 `engine / packagePath / shotId / firstFrameTimeSec / lastFrameTimeSec / frames / attachedAt` —— **不含 `firstFramePath` / `lastFramePath` / `controlVideoPath`** |
| `resolvePrevizArtifacts()` 读取字段 | **只认** `p.firstFramePath` / `p.lastFramePath` / `p.controlVideoPath` / `p.packagePath` |
| 后果 | `{{FIRST_FRAME}}` / `{{LAST_FRAME}}` / `{{CONTROL_VIDEO}}` 恒为空字符串 |
| `data/workflows/h3.json` | 这 4 个占位符**只出现在 `_comment` 说明里**；节点表无任何 `LoadImage` / 视频加载节点 |
| Seedance 适配器 | 只发文本 `content: [{type:'text', text: prompt}]`，**不带任何参考图** |

**结论：预演产物对最终成片贡献为零。** 这是"用 3D 预演解决提示词表达"这一核心设计意图的落空点。

### 🔴 断点 2：生成后端从未真实跑通

| 项 | 实测 |
|---|---|
| `data/outputs/` 唯一产物 | `job_mw3d1gbj952ft.mp4`（2,848,208 B） |
| 该文件 SHA-256 | `05bd857a…7dbd8f5` |
| `assets/placeholder.mp4` SHA-256 | `05bd857a…7dbd8f5` |
| **结论** | **与占位样片逐字节相同** —— 是 ffmpeg 当时未安装时的 fallback 副本，非真实生成 |

补充核实：当前 ffmpeg 已就位，`runMock` 的 lavfi 链路实测 exit=0 能真出片（1344×768/72帧/3s）。所以 mock 是好的，**坏的是"只有 mock"**。

### 🔴 断点 3：预演产物本身有 3 个质量缺陷

| # | 缺陷 | 实测证据 |
|---|---|---|
| 3.1 | **尾帧取错镜头** | `lastFrame.timeSec=3.75` 处 `fov=42`、相机 `(2.6,2.2,6.2)`；而首帧是 `fov=50`、`(0,2.2,7.2)`。末帧时间落在镜头边界上，取到了**下一镜头**的机位 |
| 3.2 | **渲染丢颜色** | `frame_0000.png`（1600×900）实测：`#ff7a66` 命中 **0**、`#55c2ff` 命中 **0**、全图饱和像素 **0/1,440,000**。演员全灰白，与 UI 里红/蓝显示不一致 |
| 3.3 | **控制视频时长不足** | `control.mp4` 实测 `duration=0.5s / nb_frames=12 / 24fps`，而镜头时长 **3.75s** —— 只有 13% 的时长，不能作为时长对齐的控制信号 |

### 🟠 断点 4：任务可靠性

| 项 | 实测 |
|---|---|
| `maxConcurrentLocal` | 在配置里定义 1 次，**全文无任何读取方** → 并发闸门不存在 |
| `cancel` | `job.status = 'cancelled'` 后返回，**不终止执行**；h3 轮询每 3s 的 `updateJob` 会把状态覆盖回 `completed` |
| 崩溃恢复 | 无任何 `running → interrupted` 扫描逻辑，进程崩溃后任务永挂 |
| 后果预测 | 接上真后端后将直接导致**显存冲突 / 重复计费** |
