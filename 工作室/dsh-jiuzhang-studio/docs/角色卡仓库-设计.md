# 角色卡仓库 · 设计说明

> 本文档先于实现编写，用于固定设计意图。实现完成后作为该模块的权威说明。

---

## 一、问题

现有流程里，角色一致性靠**每镜手动挂参考图**。这有三个问题：

1. **重复劳动**：同一个角色在 10 个镜头里要挂 10 次。
2. **无权威来源**：参考图可能是原立绘、也可能是拆解图，每次选的不一定一样。
3. **缺文字约束**：只有图，没有"这是个什么角色"的文字设定。模型只能看图猜。

用户要的是一个**数据包**：一个角色 = 拆解图 + 设定文字（可选原立绘），项目里选几个角色，每个分镜生成时自动带上。

## 二、数据模型

### 2.1 角色卡（CharacterCard）

```
data/vault/cards.json        索引
data/vault/<cardId>/         每张卡一个目录（可选，图仍走 assets/）
```

```jsonc
{
  "id": "card_xxx",
  "name": "三角初华",              // 必填，角色的权威名字
  "aliases": ["初华"],             // 提示词里可能出现别的叫法
  "description": "…",              // 文字设定，会进提示词
  "traits": ["金发", "紫瞳"],       // 结构化标签，便于提示词拼装
  "personality": "…",              // 演出参考
  "voiceDesc": "…",                // 音色（未来给音频模型）

  // 图片：按用途分槽位，不是一堆散图
  "images": {
    "sheet":  "assets/xxx.png",    // 拆解图/设定卡（首选，一致性最强）
    "origin": "assets/yyy.webp",   // 原立绘（保真，但信息密度低）
    "heads":  [],                  // 表情/头部特写（可选）
    "extras": []                   // 其他参考
  },

  // 生成时用哪张、用几张
  "refPolicy": {
    "mode": "sheet-first",         // sheet-first | origin-first | sheet-only | both
    "maxImages": 2                  // 这张卡在**一个镜头**里最多占几张参考图
  },

  "createdAt": 0, "updatedAt": 0
}
```

**为什么按槽位而不是扁平数组**：模型对"设定卡"和"原立绘"的用途不同。
设定卡布局规整、分解清晰，最适合做一致性锚点；原立绘保留真实画面氛围但只有单一角度。
分开存才能让 `refPolicy` 有东西可选。

### 2.2 项目 ↔ 角色卡绑定

```
项目 shot / project 上存 cardIds: ["card_a", "card_b"]
```

不复制角色卡内容，只存 id 引用。角色卡更新后所有项目自动生效。

## 三、关键约束：参考图数量预算

这是设计的**硬边界**，必须先算清楚。

### 3.1 事实（来自 ComfyUI 源码，非猜测）

| 约束 | 值 | 出处 |
|---|---|---|
| `ref_images` 上限 | **9** 张 | `nodes_minimax_h3.py:288` `max=9` |
| 参考视频 | 3 段 | 同上 `ref_videos` |
| 参考音频 | 3 段 | 同上 `ref_audios` |
| 每张图缩放 | `ref_image_size=match` 时按生成面积等比缩小 | `:317-323` |
| `max` 模式 | 短边固定 2048，**显著变慢** | `:321` |

H3 官方另有"参考文件合计 ≤12"的说法（项目 `h3-prompt.js` 里记为 `totalRefs: 12`）。

### 3.2 预算分配

9 张图不是"一个角色能放 9 张"，而是**整条提示词共享**。所以：

```
每个角色的图数 (来自 refPolicy.maxImages，默认 2)
  × 选中角色数
  + 场景/道具参考
  + 首尾帧
  ≤ 9
```

举例：
- 2 个角色 × 2 张 = 4 张 → 还剩 5 张给场景/首尾帧，安全。
- 4 个角色 × 2 张 = 8 张 → 只剩 1 张，**必须警告**。
- 5 个角色 × 2 张 = 10 张 → **超限，必须裁剪或报错**。

### 3.3 裁剪策略（超限时）

按优先级取，**不是简单截断**：

1. 角色的 `sheet`（设定卡）—— 优先级最高，一致性全靠它
2. 首尾帧（previz）—— 有明确构图约束
3. 角色的 `origin`（原立绘）—— 补充保真度
4. 场景/道具 —— 优先级最低

超限时：先丢场景/道具，再丢原立绘，最后才丢设定卡。**丢掉的必须明确告知**，不能静默。

## 四、文字怎么进提示词

角色卡的 `description` / `traits` 不该无脑拼进去。H3 的 Ref2VA 提示词有固定结构
（`h3-prompt.js` 的六段式，`<Picture i>` 指向第 i 张参考图）。

所以角色卡要做两件事：

1. **占住图的位置**：知道自己的第 i 张图在 `ref_images` 里是第几张 → 拼出 `<Picture N>`。
2. **提供主体定义**：把 `description` 填进 `subject_definitions` 段，并标注"外观来自 `<Picture N>`"。

这与「人设卡拆解提示词不描述图片」不矛盾：
- **拆解时**：图是待拆解的素材，描述它会干扰。
- **生成时**：图是角色的权威形象，用文字**指明它是谁、要看哪张图**，是必要的。

区别在于：拆解时不复述外观，生成时用文字**索引**图片而不复述外观细节。

## 五、API 设计

```
GET    /vault/cards                 列表（支持 ?q= 搜索）
POST   /vault/cards                 新建
GET    /vault/cards/:id             详情
POST   /vault/cards/:id             更新
POST   /vault/cards/delete          删除
POST   /vault/cards/:id/from-sheet  从拆解任务一键建卡（拆解完成后调用）
GET    /vault/meta                  可用槽位/策略/限额

POST   /projects/:id/cards          设置项目选中的角色卡
GET    /projects/:id/cards          读项目的角色卡绑定
GET    /vault/plan?projectId=&shotId=  预览：这个镜头会带哪些图/文字、是否超限
```

`/vault/plan` 是关键——让用户在生成前看到"这次会传几张图、分别是哪张、超没超"，而不是生成完才发现丢图。

## 六、与现有链路的接法

```
shot.characterRefs  (已有字段，保持兼容)
       ↑
   resolveRefImages()   ← 在这里合并角色卡的图
       ↑
   角色卡仓库
```

**兼容策略**：`characterRefs` 继续支持裸路径（老数据不动）；
新增 `cardIds` 走仓库。两者合并时去重，仓库的排前面（优先级高）。

分镜生成（`runH3Local`）只改 `resolveRefImages` 一处 + 提示词拼装一处，
不动 ComfyUI 接线（那层已经验证过是对的）。

## 七、非目标（明确不做）

- ❌ 不做角色的"版本历史"（改了就改了）
- ❌ 不做自动从立绘提取特征（那是拆解图的活）
- ❌ 不引入向量检索/相似度匹配（角色卡是显式选择，不猜）
- ❌ 不改 ComfyUI 工作流结构
