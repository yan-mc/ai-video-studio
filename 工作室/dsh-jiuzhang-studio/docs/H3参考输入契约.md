## 一、四种参考输入

`MiniMaxH3ReferenceToVideo` 接受四类参考：

| 输入 | 类型 | Autogrow 前缀 | 上限 |
|---|---|---|---|
| `ref_images` | `IMAGE` | `ref_image_` | **9** |
| `ref_videos` | `IMAGE`（**帧序列**，不是 VIDEO） | `ref_video_` | **3** |
| `ref_video_audios` | `AUDIO` | `ref_video_audio_` | **3** |
| `ref_audios` | `AUDIO` | `ref_audio_` | **3** |

另有项目层面的保守约束「参考文件合计 ≤ 12」。

**注意 `ref_videos` 的单位是帧序列（IMAGE batch），不是视频文件。**
加载视频要：`LoadVideo` → `GetVideoComponents` → 取 `IMAGE`（帧）与 `AUDIO`（音轨）。

## 二、提示词里的标签（最容易错的地方）

标签由 `comfy/text_encoders/minimax.py:208-230` 生成：

```python
counters = {"image": 0, "audio": 0, "video": 0}
for item in minimax_ref_items:
    counters[kind] += 1
    if kind == "image":   add_text("<Picture %d>: " % counters["image"])
    elif kind == "audio": add_text("<Audio %d>: " % counters["audio"])
    elif kind == "video": add_text("<Video %d>: " % counters["video"])
```

### 关键规则

**① 编号是「按类型各自累加」**，不是全局一个序号。

**② `<Audio j>` 会把视频自带音轨也算进去。**

各类型在 `ref_items` 里的压入顺序是：

```
ref_images 循环     → {"type":"image"}            → <Picture 1..N>
ref_videos 循环：
    若有音轨        → {"type":"audio"}            → <Audio j>   ← 先压音频
    → {"type":"video"}                            → <Video k>   ← 再压视频
ref_audios 循环     → {"type":"audio"}            → <Audio j>
```

### 实例

配置：`ref_images = [A]`，`ref_videos = [V1（带音轨）]`，`ref_audios = [S1]`

**实际呈现顺序**：

```
<Picture 1>  ← A
<Audio 1>    ← V1 的音轨      ← 注意！它占了 Audio 1
<Video 1>    ← V1
<Audio 2>    ← S1             ← 独立音频是 Audio 2，不是 Audio 1
```

**如果按「独立音频 = Audio 1」去写提示词，就全错了。**

规则总结：
- 第 k 个参考视频 → `<Video k>`
- 第 k 个参考视频的**音轨** → 占用 `<Audio>` 的下一个序号
- 独立参考音频排在所有视频之后继续编号

## 三、尺寸与时长约束

| 参数 | 约束 | 出处 |
|---|---|---|
| `width` / `height` | 32 的倍数；官方档位 864×480 / 960×544 / 1056×608 / 1344×768 | 节点 step=32 |
| `length` | **17k+5** 网格（124 ≈ 5s @24fps），训练范围约 124–362 | 节点 tooltip |
| `ref_image_size` | `match`（缩到生成面积）/ `max`（短边 2048，**显著变慢**） | 节点 tooltip |
| 参考图 | 大于 2048 短边会被缩小，**从不放大** | `:287` |
| 参考视频 | 至少 5 帧；内部裁到 `n % 17 == 5` | `:345-349` |
| 参考视频 | 超过目标帧数会被截断到 `frame_count` | `:342` |
| 参考音频 | 每段 2–15 秒 | 项目 `h3-prompt.js` 的 H3_LIMITS |

## 四、接线的两种实现路径

### 路径 A：参考图（已实现）

```
LoadImage.image → ref_images.ref_image_N
```

### 路径 B：参考视频 + 音轨（本次新增）

```
LoadVideo(file) ──VIDEO──> GetVideoComponents
                              ├── IMAGE  → ref_videos.ref_video_K
                              └── AUDIO  → ref_video_audios.ref_video_audio_K
```

**注意编号必须对齐**：`ref_video_3` 的音轨必须是 `ref_video_audio_3`。
源码 `:335` 的配对逻辑：

```python
soundtrack = ref_video_audios.get("ref_video_audio_" + name.rsplit("_", 1)[-1])
```

即按**编号**配对，不是按数组顺序。

### 路径 C：独立参考音频（本次新增）

```
LoadAudio(audio) ──AUDIO──> ref_audios.ref_audio_N
```

## 五、实现时必须保证的不变量

1. **编号与接线严格对应**：`<Picture N>` ↔ `ref_images.ref_image_N`，
   `<Video K>` ↔ `ref_videos.ref_video_K`，`<Audio J>` ↔ 按上述规则推出的音频槽。
2. **视频与其音轨同号**：`ref_video_K` 与 `ref_video_audio_K` 必须来自同一个文件。
3. **没有音轨的视频，不产生 `<Audio>` 标签**（源码里 `soundtrack is None` 时不压 audio）。
4. 超限时按优先级裁剪，且**裁剪后所有编号重排**。
