# 06 · MiniMax H3 本地部署与推理实操（截至 2026-11-03）

> **版本**：2026-11-03（北京时间）。
> **证据基准**：MiniMax 官方部署页标注 "Last reviewed 2026-08-26"；SGLang/vLLM-Omni/comfy 文档核验于 2026-10-31 前后；社区实测数据截至 2026-10-13。
> **证据分级**：`[官方]` MiniMax 官方文档/模型卡/定价页/许可原文；`[上游实测]` SGLang、vLLM-Omni Cookbook 的官方基准（MiniMax 明确声明"非 MiniMax 验证硬件"）；`[社区实测]` 第三方仓库真机数据；`[估算]` 本报告按公开单价/功耗/折旧公式推算（含推断，非实测）；`⚠️` 未能交叉核实或存在版本漂移风险。
> **边界**：本文只讨论可下载的 **H3-Base（FL2VA / Ref2VA）**。**H3-Context-IR 与 H3-Regenerate-2K 未开源**，完整 2K 链路必须走官方 API（或用 NVIDIA/社区的第三方重生成方案替代）。许可排除美/欧/英/韩，中国大陆属"适用领土"，但商用有营收门槛与标注义务（见第 8 节）。

## 0 一页纸结论（先看这 12 条）

1. **官方给两条路，不是一条**：交互创作走 ComfyUI（Comfy-Org 转换/量化权重）；可复现服务走 SGLang（官方混合 BF16/FP32 权重）。两者**数值基线不同**，不能混用 benchmark 结论 `[官方]`。
2. **官方参考配置是单节点 8×NVIDIA B200 + Ulysses degree 8 + 组件常驻**，但官方原话是"参考配置，不是最低硬件要求"，且**没有公布该配方的延迟/峰值显存** `[官方]`。
3. **权重仓库固定 revision `42ed227ee7df40d41602854ae760620d6eb651fe`，SGLang 固定源码 commit `2511743bd784e69e5a81ca3d926a000711dae4ab`**；H3 支持是 SGLang v0.5.17+ 的 **Preview**，官方明说"不是稳定发布契约"，升级前必须重读文档 `[官方]`。
4. **只开源两个任务分区**：H3-Base-FL2VA（t2va/fl2va）与 H3-Base-Ref2VA（ref2va）。**Context-IR 与 Regenerate-2K 不开源**，本地只能出 768p；2K 需官方 API 或 NVIDIA Open-H3-Regenerate-2K 等三方方案 `[官方]`。
5. **输出规格统一**：MP4 / H.264 / 24 FPS / AAC 立体声 32 kHz；短边 768、尺寸 32 的倍数、原生 16:9 为 1344×768；时长 4–15 秒；帧数吸附到 `17k+5` 网格（107–362 帧）`[官方]`。
6. **磁盘与主机内存是隐形门槛**：权重约 **108 GB**（官方引上游 Cookbook）；vLLM-Omni 口径**每个 checkpoint 分区约 134 GiB（落盘约 135 GiB）**，两个分区约 **270 GiB**；双卡 offload 配方要求**至少 200 GiB 可用系统内存、推荐 384 GiB** `[官方][上游实测]`。
7. **生成速度差 30 倍量级**：8×B300 跑 5 秒/50 步为 **18–19 秒**；4×H200 为 **74–84 秒**；2×RTX 5090 为 **约 9 分 20 秒**；单张 4090 768p/20 步 **约 6.8 分钟**，int8 约 5 分钟，加 Spectrum 可到 2.7 分钟 `[上游实测][社区实测]`。
8. **消费级门槛比想象低，但"舒服线"在 16–24GB**：SGLang 官方给出 **12GB 显存 + 32GB 主机内存跑 480P** 的实测配方（16.8–18.7 s/it）；主机内存充足时 16GB 显存可到 6.01 s/it；ComfyUI 社区口径是 **16GB 显存 + 32GB 内存可"稳定制作"、24GB 更好**，8GB 靠 Q2_K GGUF（6.7GB）也能跑但分钟级 `[上游实测][社区实测]`。
9. **量化/蒸馏生态已经分层**：NF4（DiffSynth，最低约 **7GB 显存**）、INT8 ConvRot、NVFP4（仅 Blackwell CC 10.0+）、GGUF（Q2_K 6.7GB–Q5 13.9GB）、Turbo 4/8 步 LoRA、FastH3、VDN-H3、Hyperflow、Spectrum、Latent Upscaler——**显存不够时"低分辨率 + 4 步 + 潜空间放大"是性价比最高路线** `[社区实测]`。
10. **服务化接口"半兼容"OpenAI**：SGLang 的 `/v1/videos` 是 MiniMax 风格 JSON（`task`/`conditions`/`target`）；vLLM-Omni 的 `/v1/videos` 是 OpenAI Videos 风格 multipart（`prompt`/`size`/`seconds`/`extra_params`）。**两者都要自己写适配层**，不存在"直接当 OpenAI 接口用"的零成本路径 `[官方][上游实测]`。
11. **成本结构反转**：官方 API 768P **$0.08/秒**（5 秒 $0.40）；8×B200 云按 $7.5/卡·时，5 秒片 ≈ **$0.32**（100% 利用率）——**云上自建只比 API 便宜约 20%，利用率低于 80% 就反超**。本地自有 4090 的边际成本可低到 **约 $0.05/条**，但慢 8–10 倍。规模 > 数千条/年、且能跑满卡时，自建才划算 `[官方][估算]`。
12. **许可不是"开源即自由"**：排除美/欧/英/韩；年营收 > 2000 万美元需书面授权；商用 UI 必须**显著标注 "MiniMax H3"**；不得用其输出改进其他 AI 模型；提供 Hosted Service 必须实现防护措施。中国大陆自用/商用可行，但公开服务还要叠加国内生成式 AI 备案与 AI 内容标识义务 `[官方][法规]`。

## 1 官方部署路径

### 1.1 三条路径与各自边界

| 路径 | 适合谁 | 接口 | 权重 | 验证边界 |
|---|---|---|---|---|
| **ComfyUI 本地工作流** | 交互创作、提示词迭代、关键帧/参考素材 | 可视化节点图 + Template Library | Comfy-Org 发布的分片+量化转换权重（INT8/NVFP4 等） | 与官方混合 BF16/FP32 **数值基线不同**；官方未公布最低显存/性能 |
| **SGLang 自托管 API** | 可复现服务、应用集成、团队共享 | 异步 `/v1/videos`（JSON 请求体） | 官方 `MiniMaxAI/MiniMax-H3` 原生权重 | 固定 8×B200 FL2VA 参考；消费卡/量化配方属"上游配置"，非 MiniMax 验证 |
| **vLLM-Omni 自托管 API** | 想一个服务同时挂 FL2VA+Ref2VA、要 OpenAI 风格、要 AMD | `/v1/videos` + `/v1/videos/sync`（multipart） | 官方权重 | 社区维护、**Experimental**；单服务双 DiT 共享编码器/VAE |

> 官方定位：想在工作站上可视化调整工作流 → ComfyUI；需要 HTTP 服务、可复现服务器配置或应用集成 → SGLang；vLLM-Omni 是"上游替代方案"，不是官方可复现基线 `[官方]`。

### 1.2 官方硬件与环境基线

| 要求 | 参考值 | 来源状态 |
|---|---|---|
| GPU | 单节点 8×NVIDIA B200 | SGLang 已验证拓扑 |
| 精度与放置 | 官方混合 BF16/FP32 权重，组件常驻 | 上游参考路径 |
| 主机内存 | 该 B200 配方未公布 | 部署前自行确认 |
| 本地磁盘 | 精确值未公布；上游 Cookbook 称权重约 **108 GB** | 另需为下载元数据、输出预留 |
| 互联 | 最低值未公布 | 建议高带宽单节点 |
| 系统 / Python | Linux + **Python 3.12** | 官方源码安装环境 |
| CUDA / 驱动 | **未公布 H3 专用最低版本** | 需兼容 B200、PyTorch 与 pin 住的 SGLang commit |
| 其他依赖 | git、curl、jq、ffmpeg、兼容的 NVIDIA 驱动、CUDA runtime | 官方明确列出 |

> 官方原话："不要把未公布的要求理解为没有要求"。`[官方]`
> 补充口径（vLLM-Omni）：**每个 checkpoint 分区约 134 GiB BF16 safetensors（落盘约 135 GiB）**，两个分区约 270 GiB；**双卡 offload 至少 200 GiB 可用系统内存、推荐 384 GiB**；SGLang Cookbook 更进一步给出 108GB 拆分：**DiT 61.73GB + 文本编码器 46.18GB** `[上游实测]`。

### 1.3 SGLang Quickstart（官方五步，含参数解读）

**① 安装 pin 住的 SGLang 源码**

```bash
export MINIMAX_H3_WORKDIR="$PWD/minimax-h3-deploy"
mkdir -p "$MINIMAX_H3_WORKDIR"
git clone https://github.com/sgl-project/sglang.git "$MINIMAX_H3_WORKDIR/sglang"
cd "$MINIMAX_H3_WORKDIR/sglang"
git checkout 2511743bd784e69e5a81ca3d926a000711dae4ab
python3 -m pip install --upgrade uv
uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install -e "python[diffusion]" --prerelease=allow
uv pip install "huggingface_hub==1.28.0"
sglang --version
```

> 这个 commit pin 替代了 H3 支持早期常见的可变 `main`/`dev`/无版本预发布安装 `[官方]`。

**② 下载 pin 住的 FL2VA 分区**

```bash
export HF_HOME="$MINIMAX_H3_WORKDIR/hf-cache"
export MINIMAX_H3_MODEL_DIR="$MINIMAX_H3_WORKDIR/model"

hf download MiniMaxAI/MiniMax-H3 \
  --revision 42ed227ee7df40d41602854ae760620d6eb651fe \
  --include "model_index.json" "FL2VA/*" \
  --local-dir "$MINIMAX_H3_MODEL_DIR"
```

> **关键**：`--model-path` 必须指向**仓库根目录**（含 `model_index.json`），**不要指向 `FL2VA/` 子目录**，SGLang 通过 `--model-variant fl2va` 自己选分区 `[官方]`。国内镜像 `MiniMax/MiniMax-H3`（ModelScope）可用，但官方明确"与 HF pin 住 commit 的 revision parity 未文档化"，**不作为可复现基线**；内网部署先用联网机下载完整目录再拷贝，并设 `HF_HUB_OFFLINE=1` `[官方]`。

**③ 启动 FL2VA 服务**

```bash
HF_HUB_OFFLINE=1 sglang serve \
  --model-path "$MINIMAX_H3_MODEL_DIR" \
  --model-variant fl2va \
  --num-gpus 8 \
  --tp-size 1 \
  --ulysses-degree 8 \
  --encoder-parallel auto \
  --performance-mode speed \
  --host 127.0.0.1 \
  --port 30010
```

| 参数 | 含义 | 实践要点 |
|---|---|---|
| `--model-variant fl2va` / `ref2va` | 选任务分区 | **一个服务只能服务一个分区**；ref2va 请求不要发给 FL2VA 服务 |
| `--num-gpus N` | 使用 GPU 数 | 必须与并行度乘积一致（`tp×ulysses×ring` 等） |
| `--tp-size K` | 张量并行：按权重切 DiT/编码器 | 省显存；每 block 多一次 all-reduce，官方 H200 上比纯 Ulysses 慢 |
| `--ulysses-degree U` | 序列并行（Ulysses）：按 packed token 序列切、注意力处 all-to-all | **纯 Ulysses 会在每张卡复制完整 DiT，不是小显存容量路径**；U 通常等于单节点卡数 |
| `--encoder-parallel auto/fold/replicate` | 32B Qwen3-VL 文本编码器的放置策略 | `auto` 在 bs=1 时等价 `fold`；`replicate` 每卡一份，峰值显存 **+约 40GB/卡**且不提速；**跨节点必须显式 `replicate`** |
| `--performance-mode speed/memory` | 速度优先 vs 显存优先 | `speed` 故意保持 DiT eager（torch.compile 会改变数值输出）；`memory` 走 layerwise offload |
| `--host/--port` | 监听地址 | Quickstart 只监听 127.0.0.1，**无公网入口、无鉴权** |

**④ 就绪探针**

```bash
curl --fail --retry 60 --retry-delay 10 --retry-all-errors \
  http://127.0.0.1:30010/health
# 就绪返回：{"status":"ok"}
```

> `/liveness` 只证明 HTTP 进程在收请求；**`/health` 在模型加载与 warmup 完成前一直返回 503**。首次加载 + warmup 可能**数分钟** `[官方]`。

**⑤ 提交、轮询、下载、验流**

```bash
video_id=$(
  curl -fsS -X POST http://127.0.0.1:30010/v1/videos \
    -H "Content-Type: application/json" \
    -d '{
      "model": "MiniMaxAI/MiniMax-H3",
      "prompt": "At night, three cats perform with tiny brass instruments in a warm living room, with movement synchronized to the music.",
      "seconds": 5,
      "task": "t2va",
      "conditions": [],
      "target": {"short_edge": 768, "aspect_ratio": "16:9", "duration_seconds": 5.0},
      "num_outputs_per_prompt": 1,
      "num_inference_steps": 50,
      "flow_shift": 12.0,
      "audio_flow_shift": 3.0,
      "seed": 1101
    }' | jq -r '.id'
)

while true; do
  job=$(curl -fsS "http://127.0.0.1:30010/v1/videos/${video_id}")
  case "$(printf '%s' "$job" | jq -r '.status')" in
    completed) break ;;
    failed) printf '%s\n' "$job" | jq . >&2; exit 1 ;;
    *) sleep 5 ;;
  esac
done

curl -fsS -L "http://127.0.0.1:30010/v1/videos/${video_id}/content" -o out.mp4

ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels \
  -of json out.mp4
```

### 1.4 `/v1/videos` 请求体字段（SGLang 路径，MiniMax 风格）

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `model` | string | `MiniMaxAI/MiniMax-H3` | 服务端模型 ID |
| `prompt` | string | 电影化多镜头描述 | H3 支持一段 prompt 内写镜头、运镜、对白、音效、音乐 |
| `seconds` | int | `5` | 顶层时长（秒） |
| `task` | string | `t2va` / `fl2va` / `ref2va` | **发错分区会立即报 task/condition 错误** |
| `conditions` | array | `[]` 或关键帧条件 | fl2va 用 1–2 张图，`role: "keyframe"`；ref2va 用参考图/视频/音频（≤9 图、≤3 视频、≤3 音频，合计 ≤12） |
| `target.short_edge` | int | `768` | 短边像素，H3-Base 固定策略 768 |
| `target.aspect_ratio` | string | `16:9` | 16:9 解析为 1344×768 |
| `target.duration_seconds` | float | `5.0` | 会吸附到 `17k+5` 帧网格 |
| `num_outputs_per_prompt` | int | `1` | 1–10 |
| `num_inference_steps` | int | `50` | base 参考值；Turbo 用 4/8（且 flow_shift 要改，见 2.4） |
| `flow_shift` | float | `12.0` | 视频 sigma 调度 shift |
| `audio_flow_shift` | float | `3.0` | 音频独立调度 shift |
| `seed` | int | `1101` | 可复现性 |
| `quality` | string | `lossless` / `high` | 请求级质量意图；`high` 动态启用 Cache-DiT（近似） |

**轮询/下载**：`GET /v1/videos/{id}` 看 `status`（`queued`/`in_progress`/`completed`/`failed`）；`GET /v1/videos/{id}/content` 取 MP4。**任务 `completed` 后要立刻下载**——任务 ID/端口属于其他服务、或结果已被清理，都会导致内容下载失败 `[官方]`。

**Ref2VA 必须起第二个服务**（同一 revision 下载 `"Ref2VA/*"`）：

```bash
HF_HUB_OFFLINE=1 sglang serve \
  --model-path "$MINIMAX_H3_MODEL_DIR" --model-variant ref2va \
  --num-gpus 8 --tp-size 1 --ulysses-degree 8 \
  --encoder-parallel auto --performance-mode speed \
  --host 127.0.0.1 --port 30011
```

### 1.5 输出规格与验收

- 容器/编码：**MP4，H.264 视频流 + AAC 立体声音频流**。
- 视频：**24 FPS**，短边 768，尺寸 32 倍数；16:9 = 1344×768；帧数 `17k+5`（107–362 帧 ≈ 4.46–15.08 秒）。
- 音频：**32 kHz 立体声**；11 种语言对白稳定支持（中/英/法/德/意/日/韩/阿/葡/俄/西）。
- 验收：`ffprobe` 至少检查 `codec_name=h264`、`r_frame_rate=24/1`、`sample_rate=32000`、`channels=2` 且文件非空。

### 1.6 官方/上游 benchmark 口径（重要警告）

官方页面**复刻的是 SGLang 上游 benchmark，且不是本文 pin 的那个 commit**，只能当"拓扑与容量指导"，不能当保证 `[官方]`。统一 workload：**1344×768 / 124 帧 / 24 FPS / 50 步 / 5 秒 T2VA / 单请求在飞**。

| 配置 | 结果 | 峰值显存/卡 | 备注 |
|---|---|---|---|
| 8×B300，FL2VA BF16，Ulysses 8，常驻 | **19.04 s** | 83,578 MB | 无损参考路径 |
| 8×B300，FL2VA FP8 | 18.03 s | 51,926 MB | 在线量化，近似 |
| 8×B300，Ref2VA BF16 | 29.12 s | 83,968 MB | — |
| 8×B300，Ref2VA FP8 | 27.12 s | 52,816 MB | — |
| 8×B300，`encoder-parallel replicate` | 同延迟 | +约 40,000 MB | 买显存换不来速度 |
| 4×H200，Ulysses 4，warmup 匹配分辨率 | **74.38 s** | 94,290 MB | H200 延迟默认 |
| 4×H200，TP2+Ulysses2，warmup 匹配 | 78.33 s | 63,490 MB | 80GB H100 配方来源 |
| 4×H200，`quality:"high"`（Cache-DiT） | 53.70 s（SSIM 0.931 / PSNR 28.16dB） | — | 近似，仅对该 workload 有效 |
| 4×H100，TP2+Ulysses2 | 13.25 s（pipeline） | 66.04 GB | 上游未公布请求形状，只能表内互比 |
| 4×H100，TP4+Ulysses1 | 13.86 s | 49.80 GB | 最省显存 |
| 2×8×H200 跨节点（Ulysses8×Ring2） | denoise/step −36.3%（T2VA）、−41.9%（Ref2VA） | — | 必须 `--encoder-parallel replicate` |
| 2×RTX 5090，TP2+DLO | **559.67 s**（denoise 525.05 + decode 33.61） | 26.3 GiB | 50 步 5 秒 |
| 单 RTX 4090 24GB，layerwise offload | 768p/20 步 **405.6 s**；int8 303.3 s | 约 18 GB | 容量路径，非延迟路径 |
| 8×MI355X / 8×MI300X | T2VA denoise 55.29 s / 167.49 s | 97.4 GB | AMD ROCm 路径 |
| 4×B300（vLLM-Omni） | 209 帧 1248×768：**86.96 s** | — | 与上面 124 帧口径不同 |

> **已知坑**：SGLang issue #34227（2026-08-26 复核）报告 `--use-fsdp-inference true` 可能**静默产出损坏的视频与音频、服务端无报错**。在修复前优先用 TP/Ulysses 放置，FSDP 只作容量手段并逐条校验输出 `[官方]`。

**官方明确"未公布"的项（部署前必须自测）** `[官方]`：
- 8×B200 参考配方的**峰值显存、延迟、主机内存、精确磁盘、互联最低要求、CUDA/驱动最低版本**；
- **消费卡最低显存与性能**（官方只有一句"ComfyUI H3 指南未公布，请在实际硬件验证"）；
- **H3 专用 CUDA/驱动基线**（只说"用与 B200、PyTorch、pin 住 SGLang commit 兼容的版本"）；
- **本地 2K/Context-IR 复现**（明确"不在自托管流程内"）；
- 官方模型卡演示的是 **4-GPU SGLang 命令，但未注明 GPU 型号**，也未公布该命令的显存/内存/延迟数据——所以"4 卡能不能跑"要按 SGLang Cookbook 的实测拓扑（4×H100/H200 等）而不是按模型卡推断。

## 2 能力矩阵：开源了什么、没开源什么

### 2.1 H3 三模块

| 组件 | 作用 | 是否在开源发布中 |
|---|---|---|
| **H3-Context-IR** | 把自由形式多模态上下文转成结构化表示（指令解析、跨模态关联、时序理解、逻辑推理）；官方称"对最终质量至关重要" | ❌ 否，托管多阶段系统，只提供 API |
| **H3-Base FL2VA / Ref2VA** | 生成 768p 视频 + 同步立体声 | ✅ 是 |
| **H3-Regenerate-2K** | 用原始上下文 + 768p 结果 in-context 重生成 2K | ❌ 否，官方称"准备好后再开源" |

因此"本地 H3 = 半条链路"：**本地能出 768p 成片，出不了官方口径的 2K**。可替代的 2K 路线有三条：
1. **本地 768p + 官方 Regenerate-2K API**（$0.05/秒输出 + $0.05/秒输入视频），5 秒约 **$0.50**，比直接调 2K API（$0.13/秒 × 5 = $0.65）便宜约 23%，且画面来自本地 `[官方][估算]`；
2. **NVIDIA Open-H3-Regenerate-2K**（HF `Efficient-Large-Model/Open-H3-Regenerate-2K`，2560×1440 三步重生成，H200 级）`⚠️ 第三方方案，非官方链路`；
3. **潜空间放大 + 二次去噪**（ComfyUI Latent Upscaler 707★ / vLLM-Omni `latent_upscale`+`latent_refine`），便宜但细节上限低于 in-context 重生成 `[社区实测][上游实测]`。

### 2.2 官方能力矩阵

| 能力 | checkpoint / task | 状态 |
|---|---|---|
| 文生音视频 | FL2VA，`task:"t2va"` | ✅ Quickstart 覆盖 |
| 首帧/尾帧/首尾帧 | FL2VA，`task:"fl2va"`，1–2 张图 `role:"keyframe"` | ✅ 需条件集合 |
| 图/视频/音频参考 | Ref2VA，`task:"ref2va"` | ✅ 需独立 Ref2VA 服务 |
| 视频到视频（V2V） | Ref2VA，`task:"ref2va"` | ✅ 是参考输入形式，不是独立 task 值 |
| Context-IR 与 2K 重生成 | 未包含 | ❌ 需 MiniMax 平台组件 |

Ref2VA 输入上限：**≤9 图、≤3 视频（每段 2–15 秒、总长 ≤15 秒）、≤3 音频（每段 2–15 秒、总长 ≤15 秒），跨模态合计 ≤12 个文件**；音频参考不能单独存在，必须至少配 1 图或 1 视频 `[官方]`。

### 2.3 ComfyUI 官方模板（Comfy-Org）

- ComfyUI **0.30.0+** 原生支持 H3 节点；模板 revision `3c1df78`，Comfy-Org 模型仓 revision `4cc1d817`（均记录于 2026-08-26 文档基线）`[官方]`。
- 官方模板库共 5 套 `video_minimax_h3_*`：**T2V、I2V、R2V、multiframe_reference（0.34.0+）、fun_controlnet_union（0.35.0+，Union 2.0 需 0.38.0+）**；另有 **FastH3**（0.36.0+）速度向模板 `[官方]`。
- 原生节点：`MiniMaxH3ImageToVideo`（T2V 不接关键帧；I2V 接 `first_frame`/`last_frame`）、`MiniMaxH3ReferenceToVideo`（R2V）、`MiniMaxH3AddGuide`（任意帧锚定）、latent noise mask（inpainting/延长） `[官方]`。
- **模型不可混用**：T2V/I2V 用 FL2VA，R2V 用 Ref2VA，两个 safetensors 不通用。
- 分辨率坑：Resolution Selector 用 **0.98 MP**（不是 1.0），因为 1.0MP 会解析成 **1376×768，超过 768×1344 面积上限**；16:9 直接 1344×768 `[官方]`。
- I2V 模板默认 **1:1、0.4MP（640×640）**，且 `first_frame` 会被拉伸到画布（不保比例）、`last_frame` 是中心裁剪——出片前必须手动改 `ref_image_size`/比例 `[官方]`。
- `MiniMaxH3AddGuide` 是**条件注入**不是 V2V：采样仍从空 latent 开始，`denoise` 不能像 V2V 那样调强度；要整段改风格用 R2V，要局部改区域用 Fun ControlNet Union `[官方]`。

### 2.4 Turbo / 少步 LoRA（版本别记错）

| 产物 | 步数 | flow_shift | 备注 |
|---|---|---|---|
| 官方 FL2V Turbo 8-step v1.0（ComfyUI 模板默认挂） | 8 | **6**（768p 版） | ComfyUI 默认 20 步，开 `turbo_mode` 走 8 步；官方提示"更快但运动/音频质量会降" |
| 官方 FL2V Turbo 4-step v1.0 | 4 | 6 | lightx2v/Minimax-h3-Turbo 发布；vLLM-Omni 实测 "5 sigma / 4 denoiser forwards，video/audio shift 6/3" |
| 官方 Ref2V Turbo 4-step v0.1 | 4 | — | R2V 模板专用；参考保真会降，要求高时回到 20–25 步 |
| 544p 8-step v1.0 | 8 | 12 | 低分辨率档；与 768p 档的 shift 不同，**不能混用** |

**硬规则**：Turbo 是时间步蒸馏（timestep-distilled），**必须同时改 `num_inference_steps` 与 `flow_shift`**；请求与已加载 artifact 不匹配会被拒（vLLM-Omni 明确"rejected, cannot silently degrade"）`[上游实测]`。另外 H3 是 **CFG 蒸馏**（guidance 烘进权重），`guidance_scale`/`negative_prompt`/`cfg_parallel_size>1` 都不适用，`guidance_scale` 必须保持 1.0。

### 4.2 关键实测细节（避免只看结论）

- **SGLang 消费级"双预算"**：12GB VRAM + 32GB 主机 → 峰值 ≤12GiB、匿名内存 24.5GiB、480P/124帧/20NFE 为 16.8–18.7 s/it（整条 318.9–356.4s）；主机内存充足 + 16GB VRAM → **6.01 s/it、整条 120.92s**（112GB 权重全部 pin 在内存，缺这 100GB 内存，每个 denoise step 要从盘上拷约 60GiB）`[上游实测]`。
- **SGLang 单张 5090 桌面机**：32GB 显存 + **60GB 主机内存** + PCIe5 SSD，864×480/124 帧/20 步整条 **112.2s**（文本编码 4.2s、每步 5.14–5.17s、解码 6.4s）；同机 ComfyUI `--fast-disk --cache-none` 为 145.9s `[上游实测]`。
- **SGLang 4090 20 步 768p（1344×768/107 帧）**：BF16+FA 405.6s；`convrot_int8`+FA 303.3s（PSNR 24.81dB）；+sol_attn 223.9s；+sage_attn 174.9s；Sage→Sol hybrid 163.8s。**50 步**同任务 BF16 1008.6s，int8+FA+Spectrum 285.3s（**3.53×**），hybrid+Spectrum 219.0s（4.61×）`[上游实测]`。
- **ComfyUI 4090-48G 真机**（同一张图、同 prompt、seed=42、I2V 124 帧/5.17 秒）：0.4MP/4 步 54.0s（峰值 48.5GB）；0.6MP/4 步 84.1s；0.6MP/6 步 117.1s；0.98MP/6 步 **243.1s**（峰值 48.1GB）。结论：**分辨率是最强杠杆**（0.4→0.98MP，面积 2.4×，每步耗时 4.6×）`[社区实测]`。
- **ComfyUI 16GB / RTX PRO 6000 96GB 对照**（约 10 秒、1152×640）：16GB 卡 4 步 + SLA **65 s / 11.0GiB**；96GB 卡 4 步 76s、8 步 103s、25 步 292s `[社区实测]`。
- **2×5090（SGLang 官方配方）**：50 步 768p 5 秒 559.67s、峰值 26.3GiB/卡；**注意 Ulysses2 组合在该机连 warmup 都没过**，被淘汰 `[上游实测]`。
- **diffusers 的内存基线**：transformer 61.7GB、conditioner 62.1GB；24–32GB 卡用 int8（torchao weight-only）+ block-level group offload，**约需 75GB 主机内存**；12–16GB 再把 video VAE leaf offload 并降到 960×544（**960×544 每步比 1344×768 快约 2.3×**）；2×80GB 可全 BF16 拆两半、2×48GB 用 int8 拆分 `[官方]`。

## 5 多卡与并行：概念、实测与可及性

### 5.1 名词解释（决定"能不能买对卡"）

| 机制 | 切什么 | 省什么 | 代价/限制 |
|---|---|---|---|
| **TP（tensor parallel）** | 权重按张量切到多卡 | 每卡权重与激活 | 每 block 一次 all-reduce；H200 上比纯 Ulysses 慢 1.6–5% |
| **Ulysses（序列并行）** | packed token 序列切分，注意力做 all-to-all | 长序列激活 | **每卡仍复制完整 DiT** → 不是小显存容量路径；head 数要能整除 |
| **Ring（跨节点）** | KV 在节点间点对点轮转 | 跨节点长序列 | 需要高带宽互联；结果不与单节点逐位一致 |
| **encoder-parallel** | 32B 文本编码器放置：fold（切）/replicate（复制） | fold 省显存；replicate 稳 | replicate 每卡 +约 40GB；跨节点必须 replicate |
| **VAE tile parallel** | 解码 tile 分到多卡 | 解码显存 | H3 只支持原生 `tile` 模式 |
| **FSDP inference** | 权重分片 + 每 block all-gather | 显存 | 慢；**有静默损坏 bug #34227**，慎用 |
| **step execution / co-batching** | 请求间按 denoise step 调度 | 调度粒度 | **实测对 H3 大请求不提吞吐**（每请求仅省 2.4%，平均延迟反而变差） |
| **cfg parallel** | CFG 正负分支并行 | — | H3 是 CFG 蒸馏，**必须为 1** |

## 6 服务化与自建网关

### 6.1 接口现状：OpenAI 兼容到什么程度

- **SGLang H3**：`POST /v1/videos`（JSON：`model/prompt/seconds/task/conditions/target/num_inference_steps/flow_shift/audio_flow_shift/seed/...`），`GET /v1/videos/{id}`，`GET /v1/videos/{id}/content`。**形状贴近 OpenAI Videos（异步任务 + 内容下载），但请求体是 MiniMax 风格**，不是 OpenAI `prompt/model/seconds/size` 那套 `[官方]`。
- **vLLM-Omni**：显式声明 "OpenAI-compatible `/v1/videos`"；字段含 OpenAI 风格 `prompt/model/seconds/size/user`，H3 专有参数放 `extra_params`（`task/duration/aspect_ratio/audio_flow_shift/...`）；另有 `/v1/videos/sync` 直接返回 MP4 字节，便于脚本与压测 `[上游实测]`。
- **公共结论**：没有"零改造直连"的 OpenAI Chat 风格 H3 接口。制作软件要么直接对接各自的 `/v1/videos`，要么在中间加一层**任务网关**（推荐）。

### 6.2 推荐架构

```
本地制作软件（分镜/角色/预演/审片）
        │  (内部统一 API: 创建任务 / 查询 / 回调 / 取消)
        ▼
┌──────────────── 自建网关（FastAPI/NestJS） ────────────────┐
│ 鉴权(API Key/JWT) · 配额与限流 · 任务表(Postgres/Redis)    │
│ 路由(FL2VA/Ref2VA/Turbo/Wan2.2) · 重试 · 幂等 · 回调/webhook│
│ 结果存储(S3/MinIO) · 生命周期清理 · 审计日志 · 成本计量     │
└───────┬──────────────┬───────────────┬───────────────────┘
        ▼              ▼               ▼
  H3 FL2VA :30010  H3 Ref2VA :30011  Wan2.2/其他 :30012
  (SGLang 1 分区)  (SGLang 1 分区)   (另一模型/实例)
```

关键职责清单：
1. **异步任务模型**：`POST /jobs` 立即返回 `job_id`，后台 worker 调后端 `/v1/videos`；状态机 `queued → running → succeeded/failed/canceled`。
2. **队列与并发控制**：每个 H3 实例**同时只跑 1 个请求**（H3 是计算受限的长序列 GEMM，co-batching 不提吞吐），所以并发数 ≈ 实例数；网关按实例维护信号量，避免 2 个请求互抢显存。
3. **失败重试**：区分可重试（OOM 后释放、实例重启、网络超时、`failed` 且同参数）与不可重试（task/condition 不匹配、参数越界、分辨率非 32 倍数、内容安全拒绝）。重试要**同 seed、指数退避、限 2–3 次**，并记录失败样本。
4. **结果存储**：`/content` 下载后立刻转存对象存储并生成缩略图/转码；**后端任务结果有生命周期，必须"完成即取"** `[官方]`。
5. **多模型路由**：按 `task`（ref2va 必须路由到 Ref2VA 实例）、按分辨率/步数（Turbo vs base）、按语言/题材（中文口播可路由 Wan2.2 或 H3）、按成本/时段（夜间批量走本地、高峰期溢出到云 API）。
6. **鉴权**：H3 服务本身**没有鉴权**，必须放在带 API Key 的反向代理/网关后面，TLS 终止在入口，后端端口只允许私网访问 `[官方]`。
7. **安全**：官方要求 Hosted Service 实现"请求配额、并发限制、输出保留策略、审计日志、滥用防护"；参考素材只读挂载、只允许专用目录；如果网关代下载远程图片/视频/音频 URL，要做**域名白名单、重定向次数、连接/读取超时、最大字节数、解码尺寸与时长限制** `[官方]`。
8. **监控**：`/health` 就绪态、队列深度、p95 延迟、每卡显存/温度/功耗、失败率与失败分类、每小时成本（token/秒数/卡时）。
9. **可观测性与回归**：每次生成记录 `model revision / sglang commit / LoRA / steps / flow_shift / seed / 分辨率 / 帧数`，否则无法做 A/B——这是 ComfyUI 官方也反复强调的"可复现团队工作流"要求 `[官方]`。

### 6.3 网关伪代码（最小可用）

```python
# FastAPI + 简单内存队列示意；生产应换 Redis/RQ/Celery + Postgres
import asyncio, httpx, uuid
from fastapi import FastAPI, BackgroundTasks, HTTPException

app = FastAPI()
H3 = {"fl2va": "http://127.0.0.1:30010", "ref2va": "http://127.0.0.1:30011"}
jobs: dict[str, dict] = {}
sems = {k: asyncio.Semaphore(1) for k in H3}   # 每实例 1 并发

@app.post("/jobs")
async def create_job(req: dict, bg: BackgroundTasks):
    job_id = str(uuid.uuid4())
    jobs[job_id] = {"status": "queued", "req": req}
    bg.add_task(run, job_id, req)
    return {"id": job_id, "status": "queued"}

async def run(job_id: str, req: dict):
    backend = H3["ref2va"] if req.get("task") == "ref2va" else H3["fl2va"]
    jobs[job_id]["status"] = "running"
    async with sems["ref2va" if req.get("task") == "ref2va" else "fl2va"]:
        for attempt in range(3):
            try:
                async with httpx.AsyncClient(timeout=3600) as c:
                    r = await c.post(f"{backend}/v1/videos", json=req); r.raise_for_status()
                    vid = r.json()["id"]
                    while True:
                        s = (await c.get(f"{backend}/v1/videos/{vid}")).json()["status"]
                        if s == "completed":
                            data = await c.get(f"{backend}/v1/videos/{vid}/content")
                            save_to_object_storage(job_id, data.content)   # 完成即取
                            jobs[job_id]["status"] = "succeeded"; callback(job_id); return
                        if s == "failed":
                            raise RuntimeError("backend failed")
                        await asyncio.sleep(5)
            except Exception as e:
                if attempt == 2: jobs[job_id].update(status="failed", error=str(e)); return
                await asyncio.sleep(5 * (2 ** attempt))

@app.get("/jobs/{job_id}")
async def get_job(job_id: str):
    if job_id not in jobs: raise HTTPException(404)
    return {"id": job_id, **jobs[job_id]}
```

### 6.4 与"本地制作软件"的接口约定（建议）

- 任务入参：`shot_id`、`prompt`（结构化：镜头/运镜/对白/音效/音乐）、`first_frame`/`last_frame`（资产 ID）、`references[]`（角色图/风格图/参考视频/音频）、`duration`（4–15s）、`short_edge=768`、`aspect_ratio`、`steps`（20 base / 8 / 4 turbo）、`seed`、`priority`。
- 任务出参：`video_url`、`duration`、`fps=24`、`resolution`、`has_audio`、`model_version`、`cost_estimate`、`license_tag`（用于追溯 H3 标注义务）。
- 幂等：以 `shot_id + 参数哈希` 作幂等键，避免制作软件重试造成重复计费。
- 取消：vLLM-Omni 支持 `DELETE /v1/videos/{id}`（有界 abort）；SGLang 无取消语义时，网关层"取消"只停止等待并存结果。

### 7.3 什么规模自建才划算

**盈亏平衡公式**：`年自建成本 = 硬件年化折旧 + 电费 + 运维人力 + 备件`；`年节省 = 年生成条数 × (API 单条价 − 本地单条边际成本)`。令两者相等求临界量。

- **1×4090 自建 vs API 768p**：API 5 秒 $0.40 ≈ ¥2.9；本地边际 ¥0.35；单条省 ¥2.55。按硬件 ¥15,000/3 年 + 运维 ¥10,000/年 ≈ ¥15,000/年 → **临界约 5,900 条/年（约 16 条/天）**；若一天能出 50 条（需 6.5 小时），约 4 个月回本（未计人力）。
- **2×5090 自建 vs API 768p**：本地单条约 ¥1.6，单条省 ¥1.3；硬件+主机 ¥55,000/3 年 + 运维 ≈ ¥2.8 万/年 → **临界约 21,500 条/年（约 59 条/天）**；所以双卡更适合"要 50 步质量 + 团队共享"，不是单纯省钱。
- **云上 8×B200 vs API**：理论成本 $0.32 vs $0.40，只在**近满负荷**时省钱；加上排队、冷启动、失败重试、运维与出口带宽，**中等利用率下不如直接调 API**。
- **结论**：`个人/小团队（<20 条/天）→ API + 偶发本地；工作室（20–100 条/天、要求数据不出内网/可定制）→ 1–2 张 4090/5090 自建 + API 兜底；规模化（>100 条/天或强合规）→ 4–8 卡云/自建 + 网关调度`。
- **隐藏成本清单**：模型/框架升级（H3 支持仍是 Preview）、驱动/CUDA 兼容、失败重试算力、对象存储与出网带宽、人工排障（一张 4090 出问题就停线）、以及 2026 年 GPU 渠道溢价导致的"折旧基数上浮"。

3. 做"给第三方用的生成服务"= Hosted Service，需要内容审核、滥用防护、审计日志与举报通道；**SGLang 本身不提供这些**，官方也明确说"这些控制就绪后才应改 `--host 0.0.0.0`" `[官方]`。

> 另注：ComfyUI 官方页面称"本地生成输出的**商业使用**需 MiniMax 商业许可，Comfy 是唯一官方转售渠道"——这与社区许可原文（营收门槛 + 标注义务）**口径不完全一致**，⚠️ 商用前建议直接向 MiniMax/Comfy 书面确认，避免渠道口径差异 `[官方][⚠️]`。

### 8.2 中国大陆合规要点（叠加义务）

1. **AI 内容标识**：《人工智能生成合成内容标识办法》（2025 年 3 月发布，2025-09-01 施行，⚠️ 以官方原文与最新解读为准）要求**显式标识 + 隐式标识**：显式 = 文字/声音/图形等用户可感知的标识；隐式 = 在文件数据中添加、不易感知的技术标识。落地到短视频：片头/角标"AI 生成"、元数据写入生成信息（模型名、版本、生成时间、任务 ID） `[法规]`。
2. **生成式 AI 服务管理**：向境内公众提供文本/图片/音频/**视频**生成服务适用《生成式人工智能服务管理暂行办法》；具有舆论属性或社会动员能力的需**安全评估 + 算法备案**（含变更/注销） `[法规]`。
3. **内容安全**：H3 本地部署**没有云端内容审核**；一旦对公众提供服务，需自建审核（提示词 + 输出双向）、违规处置与留痕。
4. **深度合成/肖像权/著作权**：R2V 锁角色、v2v 改视频涉及**肖像权、著作权、表演者权**；商用要取得素材授权；不得用 H3 输出"以假乱真"而不标注（同时违反许可的 Acceptable Use 与国内标识要求）。
5. **数据出境**：本地推理天然规避数据出境；但若把素材/结果传给境外 API（如 2K Regenerate-2K），需评估数据出境合规。

### 8.3 商用前检查清单

- [ ] 部署主体与最终用户是否在 Applicable Territory？
- [ ] 年营收是否可能超过 2,000 万美元？是否需要书面授权？
- [ ] 产品 UI 是否**显著**标注 "MiniMax H3"？
- [ ] 生成文件是否带 **AI 标识（显式 + 隐式）**？
- [ ] 是否分发权重/衍生模型？NOTICE 与许可副本是否随附？
- [ ] 是否把输出用于训练其他模型？（禁止）
- [ ] 对外服务是否有审核、举报、审计与滥用防护？
- [ ] 素材/肖像/音乐版权是否清晰？

## 9 常见坑与排障清单

| 现象 | 根因 | 修复 |
|---|---|---|
| 启动即报找不到模型/分区 | `--model-path` 指向了 `FL2VA/` 子目录 | 指向**仓库根目录**，用 `--model-variant` 选分区 `[官方]` |
| 加载/首个请求报文件缺失或损坏 | 下载不完整，或目录混入其他 revision | 重跑同 revision 的 `hf download`；必要时 `--force-download`；一个目录只留一个 revision `[官方]` |
| `/liveness` 正常但 `/health` 503 | 模型仍在下/加载/warmup | 等 `/health` 返回 200 再发请求；首次 warmup 可能数分钟 `[官方]` |
| import / CUDA kernel / 算子错误 | Python、驱动、CUDA、SGLang 源码偏离 pin 基线 | 新建 Python 3.12 环境，checkout 文档 commit，重装 `python[diffusion]` `[官方]` |
| NCCL 超时 / worker 启动失败 | GPU 不可达，或可见卡数与并行度不一致 | `nvidia-smi topo -m`、`CUDA_VISIBLE_DEVICES`；首次部署保持单节点 8 卡可见 `[官方]` |
| 任务立即因 task/condition 失败 | 请求发错分区，或条件集合非法（如 ref2va 没有参考条件） | t2va/fl2va → FL2VA，ref2va → Ref2VA；ref2va 至少 1 个参考条件 `[官方]` |
| 任务 completed 但内容下载失败 | 任务 ID/端口属于别的服务，或结果已被清理 | 同 host+port 查询；**完成即下载** `[官方]` |
| 视频/音频损坏且服务端无报错 | `--use-fsdp-inference true` 触发 issue #34227 | 改用 TP/Ulysses 放置；若必须 FSDP，逐条校验输出 `[官方]` |
| 输出没声音/音画不同步 | 音频 VAE 用了 fp16 | **音频 VAE 必须 fp32** `[社区实测]` |
| `ClipLoaderGGUF` 崩溃（`TypeError: the JSON object must be str...`） | H3 的 GGUF 文本编码器缺 mmproj 视觉塔 | 文本编码器只用 **safetensors + 官方 `CLIPLoader`（type=minimax）**；低显存靠 offload 解决 `[社区实测]` |
| 分辨率报错或超面积 | 用了 1.0MP → 1376×768，超过 768×1344 上限 | 用 **0.98MP** 或直接 1344×768，尺寸取 32 倍数 `[官方]` |
| 时长被改写 | 帧数吸附 `17k+5`；最短 107 帧（≈4.46 秒） | 按网格给时长（4.46/5.17/6.0…15.08 秒） `[官方]` |
| Turbo 输出崩坏或参数被拒 | 只改了步数，没改 `flow_shift`（768p Turbo 是 6，不是 12） | steps 与 flow_shift 成对设置；请求与已加载 artifact 必须匹配 `[上游实测]` |
| 显存碎片导致 decode 阶段 OOM | decode 贴近显存上限 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`；降 `video_vae=24` 或加 resident 层 `[上游实测]` |
| 跨节点 Ref2VA 编码器崩溃 | `--encoder-parallel auto` 的 fold 决策不感知节点边界 | 跨节点**显式** `--encoder-parallel replicate` `[官方]` |
| 纯 Ulysses 扩卡后仍 OOM | 纯 Ulysses 每卡复制完整 DiT | 换 TP / 模型级 offload；Ulysses 只扩序列不扩容量 `[上游实测]` |
| 小显存开 `--dit-layerwise-resident-layers 0` 仍慢 | 每步从盘上重读几十 GB | 主机内存尽量大（pin 权重）；NVMe 必须；resident 层按显存加 `[上游实测]` |
| Cache-DiT / Spectrum / FSDP 叠加后画质崩 | 近似加速叠乘 | 同一路径只开一种近似；改前 A/B 同 seed `[上游实测]` |
| 冷启动第一个请求特别慢 | 未 warmup 目标分辨率/编译 | `--warmup-resolutions 1344x768`；首个请求不计入稳态统计 `[官方]` |
| HF 下载 403 | 权重仓库需要访问审批（gated） | 登录 HF 并申请访问；`hf auth login` `[上游实测]` |
| 驱动旧导致 SLA 节点崩 | `H3SLAAttention` 需 cu130+ | 升级驱动，或使用无 SLA 工作流 `[社区实测]` |
| 多卡请求吞吐不升反降 | 开了 co-batching | 保持 `--max-num-seqs 1`；H3 大请求不靠 batch 摊薄 `[上游实测]` |
| 服务暴露公网后被滥用 | Quickstart 无鉴权 | 放带鉴权的反代/网关后；TLS 终止在入口；配额+审计+滥用防护 `[官方]` |

## 10 落地建议（面向"本地制作软件 + H3 推理"）

**三条可落地路线（按团队规模）**

1. **内容个体/小团队（0–20 条/天，预算 < ¥2 万）**
   ComfyUI 0.30+ + 16–24GB 显存（4090/5090）+ Q4_K/fp8 + FL2V Turbo 8 步。生成 768p 4–10 秒，后期在剪辑软件拼接。省钱、门槛低；缺点是无 API、无法多人并发。
2. **工作室（20–100 条/天，要求资产/任务管理）**
   SGLang 单/双卡（2×5090 或 2×4090）+ 自建网关（第 6 节），ComfyUI 只做调试与素材。生成走异步队列，制作软件通过统一任务 API 调用；2K 用"官方 Regenerate-2K API"补齐。这条路线在**数据不出内网 + 成本可控**之间最平衡。
3. **规模化/对外服务（>100 条/天或要 To B）**
   4–8 卡 H200/B200（云或托管）+ 多实例网关（H3 FL2VA/Ref2VA + Wan2.2 + 其他），按 task/成本/地域路由；H3 仅用于高质量镜头，批量镜头走更便宜的模型；2K 全量走官方 API 或自建 Open-H3-Regenerate-2K。**必须**先完成许可与合规清单（第 8 节）。

**与制作软件的接口建议**：把"生成"抽象成"镜头任务"（shot-level job），而不是"一次 prompt 一次调用"——制作软件天然是**分镜/镜头/版本**结构，网关按 `shot_id + version` 管理结果，把 H3 的 4–15 秒限制、768p、17k+5 帧网格、音频 32kHz 这些约束在 UI 层显式化（超时长自动拆镜头、超分辨率走 2K 补链）。

**明确的"不能做"**：
- ❌ 别指望本地开源权重直接出官方口径的 **2K**（Context-IR / Regenerate-2K 未开源）；
- ❌ 别指望 8–24GB 卡跑 50 步 768p 还"实时"（分钟级是常态）；
- ❌ 别把 SGLang `--host 0.0.0.0` 直接暴露（无鉴权、无配额）；
- ❌ 别在美/欧/英/韩主体上部署权重（许可硬限制）；
- ❌ 别把 FSDP、Cache-DiT、Spectrum、量化、Turbo 同时叠满还要求"无损"。
