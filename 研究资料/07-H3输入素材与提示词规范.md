# 07 · MiniMax H3 输入数据、素材与提示词规范

> 交付定位：本文件回答用户链路中最关键的一问——**"复杂制作场景下，到底要往 H3 传什么、怎么传"**。
> 数据口径：以 **2026-11-03（北京时间）** 可抓取的 MiniMax 官方文档/模型卡/API 参考、ComfyUI 官方仓库与模板、以及公开社区实测为准。
> 标注规则：`[官方]` = MiniMax/ComfyUI 官方文档或源码；`[社区]` = 第三方可复现实测/踩坑记录；`⚠️` = 来源单一、口径冲突或未能交叉核实；`[推断]` = 本文基于证据的分析判断，非事实。
> 本文不覆盖：H3 的模型架构细节、价格与榜单（见 `02-国内闭源模型.md` / `03-开源模型全景.md`）。

## 0. 结论速查（12 条）

1. **H3 的"一次请求"是一段 4–15 秒、短边 768p、24fps、带 32kHz 立体声的完整音视频**；2K 不是一次生成出来的，而是把 768p 结果连同原始上下文**再生成**一次（H3-Regenerate-2K）。`[官方]`
2. **任务类型只有四种输入形态**：T2VA（纯文本）、I2VA/L2VA/FL2VA（精确首帧/尾帧/首尾帧，最多 2 张图）、Ref2VA（图/视频/音频参考）。**首尾帧模式与参考模式互斥，不能同请求混用。**`[官方]`
3. **参考模式硬上限**：图 ≤ 9 张、视频 ≤ 3 段、音频 ≤ 3 段，**合计文件数 ≤ 12**；每段视频/音频 2–15 秒，各自总时长 ≤ 15 秒。`[官方]`
4. **提示词有官方格式**：基础模式三段式（`integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music`），参考模式六段式（`subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music`）。正文用英文写，对白/歌词/画面文字保留原语言。`[官方]`
5. **素材引用语法是尖括号标签**：`<Picture N>` / `<Video N>` / `<Audio N>` / `<Subject N>`（如 `@图片1`→`<Picture 1>`）。编号**按模态各自从 1 开始、按连线槽位顺序**，不是按文件名。`[官方][社区]`
6. **H3 没有负向提示词**：官方 ComfyUI 模板走 `BasicGuider`，CFG 实际为 1，无负向通道；"不要出现 X"必须改写成正向约束。`[官方源码][社区]`
7. **本地开源只覆盖 768p**：开源权重是 H3-Base 的 FL2VA 与 Ref2VA 两个 checkpoint；**H3-Context-IR 与 H3-Regenerate-2K 未开源**，完整 2K 链路必须走官方 API。`[官方]`
8. **结构控制（深度/姿态/线稿/灰阶/布局）不在官方 API 里**，只能通过 ComfyUI + 社区 ControlNet-Union（Fun-Controlnet-Union 2.0：8 种条件 + 局部重绘）。这是"Blender 预演→H3"目前唯一的硬结构通道。`[官方生态][社区]`
9. **人物设定图不要直接塞"网格三视图"**：社区实测单个大网格设定图的身份保真度明显低于 2–4 张独立高分辨率照片；官方参考图短边最高按 2048px 处理，一张 3×3 网格摊薄后每格仅约 680px。`[社区]`
10. **时长按 `17k+5` 帧网格吸附**（24fps）：有效帧数 107/124/141/…/345/362，即约 **4.46–15.08 秒**；API 侧 4 秒会被吸附到 107 帧。`[官方 API][官方源码]`
11. **提示词上限 7000 字符**（生成接口）；参考模式 `detailed_description` 官方建议 350–500 英文词。2K 再生成接口的 prompt 上限放宽到 40000 字符（且必须是 Context-IR 之后真正送入模型的最终提示词）。`[官方 API]`
12. **横向看，只有 Seedance 2.5 官方原生支持"白模参考"**；H3 需要 ComfyUI ControlNet 曲线实现，Kling 4.0 走 10 张关键帧，Wan 3.0 走 20 项素材+首尾帧，Veo 3.1 只有 3 张参考图 + 首尾帧。`[官方]`（详见第 6 节对照表）

## 1. H3 能力矩阵与任务类型

### 1.1 系统三模块：输入差异的根源

H3 完整系统由三个模块串成，**"传什么"取决于你用的是哪一段**：

| 模块 | 作用 | 主要输入 | 输出 | 是否开源 |
|---|---|---|---|---|
| **H3-Context-IR** | 把自由形式的多模态上下文（文本+图+视频+音频）理解、推理、补全，转成结构化中间表示（最终呈现为一段增强后的结构化提示词） | `content[]`：text / image_url / video_url / audio_url + `duration` + `ratio` | **只返回增强提示词**（`task_type=h3_context_ir`，`content.prompt`），不生成视频 | ❌ 未开源，仅 API（`/v2/h3_context_ir`） |
| **H3-Base（FL2VA / Ref2VA）** | 生成 768p 视频 + 同步立体声；FL2VA 支持 t2va/fl2va，Ref2VA 支持 ref2va | FL2VA：文本 + 可选首帧/尾帧（0/1/2 张图）；Ref2VA：文本 + 参考图/视频/音频 | 768p、24fps、32kHz 立体声 MP4 | ✅ 开放权重（社区许可，排除美/欧/英/韩本地部署） |
| **H3-Regenerate-2K** | 用原始上下文把 768p 结果 in-context 再生成到 2K（能恢复小字与细节，不是传统超分） | **必须二选一**：① `source_task_id`（需白名单）② `content[]` 内含**恰好一个** `role=base_video` 的 768p 源视频，**并原样带上当初生成它的全部输入（含最终提示词）** + `resolution=2K` | 2K 视频 | ❌ 未开源，仅 API（`/v2/video_regeneration`） |

**关键含义**：本地部署只能做 768p；要做 2K 必须把本地结果或 API 结果交给 Regenerate-2K，并且**必须保存"那次生成真正使用的最终提示词"**——用原始用户话术去再生成会不匹配。`[官方]`

**再生成源视频的硬规格**（不满足直接拒）：必须带音轨、24fps、宽高均为 32 的倍数、面积在 768×768 与 768×1344 之间、总帧数 107–362 且为 17 的步进（约 4–15 秒）。`[官方]`

### 1.2 任务类型：每种任务"必须传什么 / 可选传什么"

| 任务 | 官方名称 / API 值 | 必须传 | 可选传 | 输出 | 本地权重 | 典型用途 |
|---|---|---|---|---|---|---|
| **T2VA** 文生音视频 | `t2va` | 一段非空 text（≤7000 字符）；`ratio` 必填且**不能是 adaptive**；`duration` 4–15 整数 | — | 视频+音频 | FL2VA | 从零生成镜头、概念片、无素材参考 |
| **I2VA** 首帧生视频 | `fl2va`（图作首帧） | text + 1 张图（`role=first_frame`；单图不填 role 默认首帧） | — | 同上 | FL2VA | 用 Blender 渲出的构图做精确首帧 |
| **L2VA** 尾帧生视频 | `fl2va`（图作尾帧） | text + 1 张图（`role=last_frame`） | — | 同上 | FL2VA | 让动作收敛到指定结束画面 |
| **FL2VA** 首尾帧生视频 | `fl2va`（两张图） | text + 2 张图（`first_frame` + `last_frame`） | — | 同上 | FL2VA | 精确控制起止构图/姿态的插值镜头 |
| **Ref2VA** 参考生视频 | `ref2va` | text + 至少 1 项参考（图/视频/音频）；**音频不能是唯一参考**（需至少 1 图或 1 视频） | 图 ≤9、视频 ≤3、音频（独立）≤3，合计 ≤12；`ratio` 可选（默认 adaptive） | 同上 | Ref2VA（**与 FL2VA 权重不通用**） | 角色一致性、动作迁移、运镜参考、音色/演唱、视频编辑与续写 |

`[官方]` 来源：模型卡输入规格、API Create 端点、官方提示词技能。**音频单独作为唯一参考在官方 API 语义下是不成立的**（须搭配视觉参考）；但当前 ComfyUI 节点会无条件迭代 `ref_audios`，社区已验证"只有独立音频"在 ComfyUI 里能跑——口径差异，引用时注明环境。`[社区][推断]`

### 1.3 官方支持的单次规格

| 维度 | 规格 | 备注 |
|---|---|---|
| 时长 | 4–15 秒（整数秒） | 本地按 17k+5 帧网格吸附，实际 107–362 帧 ≈ 4.46–15.08s |
| 分辨率 | 默认短边 768p；H3-Regenerate-2K 可到 2K | 本地画布：短边 768、面积上限 768×1344、"32 的倍数"；16:9 原生画布 **1344×768（0.98MP）** |
| 比例 | 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16（+adaptive） | t2va 必须显式选；i2va 由首帧决定（强制 adaptive）；r2va 可选 |
| 帧率 | 24 fps | 固定 |
| 音频 | 32 kHz 立体声 | 与视频同一遍联合生成（人声/音效/配乐） |
| 对白语种 | 11 种稳定支持：阿、中、英、法、德、意、日、韩、葡、俄、西 | 其他语种"不同程度支持" |
| 提示词长度 | 生成接口 ≤7000 字符/条 text；再生成接口 ≤40000 字符 | 参考模式单条 text 同样受 7000 限制 |
| 请求体 | ≤64 MB（Base64 会膨胀约 33%，大文件用公网 URL 或 `mm_file://`） | 图片/视频/音频分别另有单文件上限 |

`[官方]`

### 1.4 官方 API 的模型变体（决定"能不能上 2K/多长"）

| 模型 | 分辨率 | 时长 | 2K | 首尾帧 | 参考模式 | 备注 |
|---|---|---|---|---|---|---|
| `MiniMax-H3` | 768P / 2K | 4–15s | ✅ | ✅ | ✅ | 唯一支持 2K 与 Regenerate-2K 的档 |
| `MiniMax-H3-Highspeed` | 480P / 768P | 4–15s | ❌ | ✅ | ✅ | 质量/速度折中 |
| `MiniMax-H3-Lite` | 480P / 768P | 4–15s | ❌ | ✅ | ✅ | 参考模式暂不支持 adaptive 比例 |
| `MiniMax-H3-Max` | 480P / 768P | **5–15s** | ❌ | ✅ | ✅ | 唯一开放 `extra.prompt_expansion_mode`（disabled/balanced/quality） |

`[官方]`。另：H3 Max 还有 fal 后训练的托管版本（榜单口径见 02 文件），与上表 API 档位不是同一物，引用时别混。

### 1.5 模式互斥与边界规则（最容易踩的雷）

- **首尾帧 vs 参考模式互斥**：`content` 里出现任何 `reference_image` / `reference_video` / `reference_audio`，就不得出现 `first_frame` / `last_frame`，反之亦然。`[官方]`
- **T2VA 的 ratio 不能 adaptive**；I2VA 传别的比例会被忽略并按 adaptive 处理。`[官方]`
- **FL2VA 与 Ref2VA 是两个独立服务/权重**，SGLang 要单独起服务、ComfyUI 要换 diffusion 模型文件，不能混用；同一节点里接错权重不会报错但输出劣化。`[官方]`
- **FL2VA 官方一般偏好单镜头**（便于从首帧连续插值到尾帧）；Ref2VA 才适合多镜头/多切点。`[官方]`
- **H3 不支持"一次出 2K 并直接带结构控制"**：2K 走再生成；结构控制走 ComfyUI 社区 ControlNet（官方 API 无此输入角色）。`[官方生态][推断]`

## 2. 提示词规范

### 2.1 语言与长度建议

- **正文一律英文**；对白、歌词、画面可见文字保留原语言原文（不翻译、不改写、标点原样）。`[官方]`
- **官方建议**：参考模式 `detailed_description` 约 **350–500 英文词**；对白密集的则以"完整覆盖口播时间线"优先，不必凑字数。`[官方]`
- 上限：单条 text ≤ **7000 字符**（生成接口）；超长会被截断/拒绝，长片请拆镜头而不是堆长文。`[官方 API]`
- 语言建议：中文用户不必强行把台词翻成英文——H3 稳定支持 11 语种对白，**中文台词写中文即可**；但镜头/动作/音效等描述性文字写英文更稳（与官方训练格式一致）。`[官方][推断]`

### 2.2 基础模式（T2VA / I2VA / L2VA / FL2VA）：三段式 + 对齐指令

**固定骨架**（顺序不可变）：

```text
[仅 I2VA/FL2VA/L2VA 需要：关键帧对齐指令]

integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

**关键帧对齐指令是官方固定句式，必须放在第一行，后接一个空行**（N=最后一个镜头编号，S.SS=有效时长保留两位小数）：`[官方]`

| 模式 | 固定第一行 |
|---|---|
| I2VA | `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` |
| FL2VA | `How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.` |
| L2VA | `How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.` |

> ⚠️ S.SS 必须是你实际提交的**有效时长**（经帧网格吸附后的值，如 5 秒请求实际 124 帧 = 5.17s），不能写用户输入的名义时长。`[官方]`

**三个字段各自写什么：**

| 字段 | 内容 | 禁忌 |
|---|---|---|
| `integrated_multimodal_description` | 按播放顺序写：风格、初始构图、主体外观与位置、场景与关键道具、动作与反应、切镜、说话人、对白/演唱、同步画内声音；每个 `[Shot N]` 里按"景别构图→主体身份线索→一个主动作→可观察变化→运镜（或明确固定）→本镜头的声音/对白"顺序写 | 不要写成剧情摘要；不要堆抽象情绪词；不要把对白塞进 `overall_soundscape` |
| `overall_soundscape` | 1–4 句英文，写环境声、物理动作声、非语言人声（雨、脚步、布料、撞击、呼吸、笑） | 不重复对白/歌唱/画内音乐 |
| `non_diegetic_music` | 1–3 句英文，只写观众能听到的配乐：乐器、速度、节奏、动态变化；无配乐写 `N/A` | 不用抽象情绪词；角色能听到的音乐属于画内，写进主描述 |

**切镜与时间戳**：`[Shot 1]` 不加时间戳；后续镜头用 `[Shot N] At MM:SS.mmm, the camera cuts to ...`，切点必须严格递增且落在时长内；**只有出现新信息（主体/空间/状态/视点/时间）才值得切**，只是景别或小角度变化优先用运镜。`[官方]`

**运镜公式：运动类型 +（可选）幅度 +（可选）速度**，写成自然英文句子而不是标签堆叠。官方词表：`Zoom In/Out`、`Push In/Pull Out`、`Pan Left/Right`、`Truck Left/Right`、`Tilt Up/Down`、`Pedestal Up/Down`、`Arc Shot`、`Tracking Shot`、`Static Shot`、`Shake Slightly/Strongly`、`POV`、`Roll Clockwise/Counterclockwise`；幅度 `with small/large amplitude`；速度 `at slow/fast speed`。示例：`The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.` `[官方]`

### 2.3 参考模式（Ref2VA）：六段式 + 四类标签 + 保留强度

**固定六段顺序**：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`；六段主体均用英文。`[官方]`

**四类标签**（标签一旦分配，含义贯穿全文，不得重编号）：`[官方]`

| 标签 | 指什么 | 用法要点 |
|---|---|---|
| `<Subject N>` | 从素材中抽象出来、将在目标视频里复用/修改的**可见内容单元**：人物、动物、物体、场景、服装、道具、界面、风格、动作、表情、姿势 | 一个人物可由多份素材共同定义（外观来自图、动作来自视频），反之亦然 |
| `<Picture N>` | 作为具体帧锚点/构图参考的**单张图**（首帧/关键帧/尾帧/编辑关键帧/分镜参考） | 只用于定义人物长相/服装/场景/风格的图**不单独建 Picture 条目**，应在 Subject 定义里引用 |
| `<Video N>` | 只表示**整段视频级关系**：编辑源、续写起点、运镜/剪辑/节奏/时间结构 | 从视频里复用的人/物/动作仍要写成 `<Subject N>`；带声音≠自动产生 `<Audio N>` |
| `<Audio N>` | 独立音频或参考视频启用的同步音轨：复制全部/部分、参考音色、参考 BGM 风格、参考节奏、复用时序 | 绑定到目标说话人时复用其全局 ID，写 `<Subject N> (Sx)` |

**保真强度必须显式声明**（固定英文枚举，不可自创）：

| 视觉关系词 | 含义 | 音频关系词 | 含义 |
|---|---|---|---|
| `fully_preserved` | 参考内容的既定角色被完整保留 | `fully_copy` | 整段源音频 1:1 作为目标视频最终音轨 |
| `partially_preserved` | 仍使用，但部分特征被替换或只保留一部分 | `partially_copy` | 只复制部分时间线/音层，或复制后有增删替换 |
| `attribute_transfer` | 特征被**迁移**到另一个可识别主体（如把动作/表情/服装迁给角色 A） | `reference` | 不复制信号，只参考音色/节奏/音乐风格/台词内容/质感 |
| `weak_reference` | 只保留风格、类别、构图、氛围的大致相似 | `weak_reference` | 只保留类别或氛围的大致相似 |

`[官方]`

**summary 用任务类型前缀开头**，多关系用 ` + ` 组合且不重复：`keyframe completion` / `reference generation` / `video editing` / `video continuation` / `audio reuse` / `audio reference`。**编辑任务必须紧跟这一固定句**：`The target video is an edited version of <Video 1>.`；编辑且保留原声必须同时写 `audio reuse`，否则音轨会被"重建"。`[官方]`

### 2.4 多主体绑定：把"谁是谁"写死

官方明确：**一个素材不要给它无限职责**。写法要点：

1. 每个 `<Subject N>` 单独一行，写清"从哪个素材来、要保留哪些特征、不提供什么"；
2. 特征要"可测量+带侧别+带位置"：`a small black cross tattooed on her right cheekbone just below the outer corner of her eye`，而不是 `long hair` 这类不可测量描述；
3. 同一主体跨镜头、跨多次渲染**逐字复用**同一段身份描述（改写=漂移来源）；`[社区]`
4. 参考视频必须**限权**：`<Video 1> (camera movement and pacing): weak_reference - only the travelling path and handheld rhythm are followed; none of its people, wardrobe, location or lighting appear.` `[社区]`
5. 双人对话先用 `<Subject 1>/<Subject 2>` 绑定视觉身份，再用 `(S1)/(S2)` 绑定说话人；二者是两套编号，不要混。

### 2.5 台词、演唱、音效与画面文字

- **说话人稳定 ID**：按第一次发声顺序给 `(S1)`、`(S2)`；多人齐声 `(S1,S2)`；全程不发声的角色不编号。`[官方]`
- **台词格式**：`<d>[语言标签] 用户原话</d>`；`<d>` 内**只放语言标签和原话**，不翻译不改写；说话人的身份描述、ID、动作、语气放在 `<d>` 外。示例：`The young woman with a quiet, breathy voice (S1) says: <d>[Chinese] 今天早点回家。</d>` `[官方]`
- **画外音**：固定短语 `says in an off-screen voiceover`，并紧跟一句说明画内人物**嘴唇保持闭合**（否则容易生成对口型）。`[官方]`
- **跨切镜的同一句**：用 `<scenetrans>` 并在两段里都说明声音连续；被结尾截断用 `<cutoff>`。`[官方]`
- **画面可见文字**：用英文双引号包住并逐字保留，如 `A red neon sign reading "营业中" glows above the doorway.` `[官方]`
- **演唱镜头**：把"谁在唱、唱什么、声音从哪来"分开写——人物身份来自图、歌声来自 `<Audio 1>`、口型/表情由主描述控制；若要 1:1 用现成歌声，声明 `fully_copy`，否则用 `reference`（只借音色）。`[官方][社区]`
- **音效/环境声/配乐**：分别落在主描述（画内同步）、`overall_soundscape`（环境与物理声）、`non_diegetic_music`（观众专属配乐）三层，**三层都要写全**——漏写配乐字段，H3 仍会自己生成一段"猜的"音乐。`[社区]`

### 2.6 没有负向提示词：所有"不要"都要改写

官方 ComfyUI 模板使用 `BasicGuider`（单条件输入），**CFG 实际为 1、没有 negative 接口**；`CFGGuider` 会把推理时间翻倍且 H3 的 guidance 训练方式未公开。社区结论：**否定句会把被否定的词写进条件里**（`no second shot` 反而引入 `second shot`）。`[官方源码][社区]`

改写范式：
- ❌ `不要出现文字/字幕` → ✅ `clean surfaces, no lettering` 改为正向：`plain matte surfaces with unmarked texture`
- ❌ `手不要畸形` → ✅ `five clearly separated fingers, a firm grip`
- ❌ `不要切镜` → ✅ `one continuous shot, the camera holds a static shot throughout`
- ❌ `不要重复动作` → ✅ 用**场景状态**封口：`the muzzle is lowered, smoke drifts, the spent shell lies on the gravel`

### 2.7 三个可复制提示词模板

> 说明：以下模板按官方格式书写；`<...>` 为素材标签，需与实际连线/上传顺序一致。方括号 `[...]` 为需要替换的内容。示例默认 8 秒、16:9、768p。

#### 模板 A · 单人口播（Ref2VA：人物设定图 + 音色参考）

素材清单：`<Picture 1>` 人物正面/半身高清照（身份+服装）；`<Picture 2>` 同一人物 3/4 侧角度（可选）；`<Audio 1>` 音色参考 3–8 秒。

```text
subject_definitions:

<Audio 1> is the voice-timbre and measured delivery reference for <Subject 1> (S1).

detailed_description:

The camera holds a static shot with a very slow push in with small amplitude. <Subject 1> (S1), speaking with the calm timbre referenced from <Audio 1>, says: <d>[Chinese] 大家好，今天用三分钟讲清楚这件事。</d> She pauses, blinks once, and gives a small nod as her lips close.

overall_soundscape: Quiet room tone with a faint ventilation hum; a soft fabric rustle as she shifts her weight.

non_diegetic_music: N/A
```

#### 模板 B · 双人对话（Ref2VA：两张人物图 + 场景图 + 音色参考）

素材清单：`<Picture 1>` 角色 A；`<Picture 2>` 角色 B；`<Picture 3>` 场景/环境；`<Audio 1>`（可选）A 的音色；`<Audio 2>`（可选）B 的音色。

```text
subject_definitions:
<Subject 1> is the man in <Picture 1>, [mid-30s, short wavy brown hair, dark-grey hoodie with drawstrings].
<Subject 2> is the woman in <Picture 2>, [late 20s, long blonde hair, light-pink button-down shirt with rolled-up sleeves].
<Subject 3> is the environment in <Picture 3>, [an exposed brick wall, an orange tufted sofa, a neon sign, a wooden coffee table].
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).
<Audio 2> is the voice-timbre reference for <Subject 2> (S2).

summary:
[reference generation + audio reference] Two people talk across <Subject 3> in three shots, using <Audio 1> and <Audio 2> only as voice-timbre references.

retention_analysis:
<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - identity, hair, hoodie, drawstrings.
<Subject 2> (appears in [Shot 1], [Shot 3]): fully_preserved - identity, hair, pink shirt, rolled sleeves.
<Subject 3> (appears in [Shot 1]): fully_preserved - brick wall, orange sofa, neon sign, coffee table.
<Audio 1>: reference - timbre only, no signal copied.
<Audio 2>: reference - timbre only, no signal copied.

detailed_description:
The target video uses a warm, realistic multi-camera sitcom style with practical indoor lighting.
[Shot 1] A medium two-shot establishes <Subject 3>; <Subject 1> (S1) sits on the left of the sofa, <Subject 2> (S2) stands at the right edge of frame holding a mug. The camera holds a static shot. <Subject 1> (S1) says, <d>[Chinese] 你确定这样可行吗？</d> <Subject 2> (S2) tilts her head and replies, <d>[Chinese] 先试一版，不行再改。</d>

[Shot 3] At 00:05.800, the shot cuts to a medium close-up of <Subject 2> (S2), who smiles, sets the mug down, and turns toward the door.

overall_soundscape: Low room tone with a refrigerator hum; ceramic clicks softly when the mug meets the table; light footsteps on a wooden floor.

non_diegetic_music: Sparse acoustic guitar at a slow tempo with a quiet sustained pad underneath, fading out at the end.
```

#### 模板 C · 演唱镜头（Ref2VA：人物 + 运镜参考视频 + 歌声参考）

素材清单：`<Picture 1>` 歌手定妆照；`<Video 1>` 2–15 秒运镜参考（建议画面里没有主要人物，避免外观泄漏）；`<Audio 1>` 一段清唱/干声 2–15 秒。

```text
subject_definitions:
<Subject 1> is the singer in <Picture 1>, [shoulder-length dark hair, silver sequined jacket].
<Subject 2> is the camera path and handheld rhythm shown in <Video 1>.
<Audio 1> is the vocal signal for the singing voice of <Subject 1> (S1).

summary:
[reference generation + audio reuse] <Subject 1> performs a short singing passage on a dark stage, with the camera path from <Subject 2> and <Audio 1> reused as the complete vocal performance.

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - identity, hairstyle, sequined jacket.
<Subject 2> ([Shot 1] camera path): weak_reference - follow the travelling path and handheld rhythm only; none of its people, wardrobe, lighting or background appear.
<Audio 1>: fully_copy - <Audio 1> is reused 1:1 as the target video's vocal track.

detailed_description:
The target video is a cinematic concert look with deep blacks, a single warm key light, and haze.
[Shot 1] The shot begins on <Subject 1> in a medium close-up at center frame, holding a handheld microphone. She lifts her chin and begins to sing with <Audio 1> as the complete vocal track. The camera follows <Subject 2>'s orbiting path with large amplitude at slow speed, revealing the empty dark stage and a row of backlit haze. overall_soundscape: A large hall reverb tail wraps the vocal; faint fabric movement near the microphone; a low amplifier hum remains under everything.

```

> ⚠️ 模板 C 的关键取舍：`<Audio 1>` 用 `fully_copy` 就**不要**再描述"她会唱什么歌词"以外的自由演唱，否则模型会试图重唱；用 `reference` 则相反，保留文字描述、只借音色。二者不可混写。

## 3. 参考图 / 参考视频 / 参考音频规范

### 3.1 图片

| 项 | 官方限制（API） | 实操建议 |
|---|---|---|
| 数量 | 首帧 ≤1、尾帧 ≤1；参考图 ≤9 | 角色一致性 2–4 张足够；9 张常导致职责冲突 |
| 格式 | JPG/JPEG/PNG/WEBP/HEIC/HEIF | PNG 无损优先 |
| 单文件 | ≤30 MB | — |
| 尺寸 | 宽高 256–5760 px | 短边 ≥1024，最好 ≥1536 |
| 比例 | 宽/高 ∈ [0.4, 2.5] | 竖图 9:16 可用；超宽需裁 |
| 引擎内处理 | 参考图短边上限 2048px（`ref_image_size=max`）；`match` 会缩到生成画布像素面积 | 身份优先时设 `max`（更慢） |

`[官方]`

**人物三视图怎么用（重要，和直觉相反）：**

- **不要**把一张"正/侧/背+表情+手部"的 3×3 **网格设定图**直接作为唯一身份参考。社区实测：网格图整体被缩放，`max` 模式下 3×3 每格仅约 680px，而单张照片有 2048px；网格的框线、留白、重复人像还会作为可见内容干扰场景。`[社区]`
- **推荐**：把三视图**拆成独立单张**（正面全身、3/4 侧、背面、面部特写各一张），按镜头实际会露出的角度挑 2–4 张。
- 三视图适合作为**设定阶段的内部资产**与"分镜/造型卡"，以及喂给 RefMod/LoRA 训练；分镜板可作为 `<Picture N>` 的 storyboard reference 声明"它只提供视点、主体位置与镜头顺序"。`[官方][社区][推断]`
- 多张图定义同一人时，合并成一个 `<Subject>` 并写明每张图提供什么：`<Subject 1> is the woman whose appearance comes from <Picture 1> and whose walking motion comes from <Video 1>.` `[官方]`

**是否接受白模/灰模/姿态图/深度图/分割图？**

| 输入类型 | H3 官方 API | H3 本地 ComfyUI | 说明 |
|---|---|---|---|
| 白模/灰模渲染图 | ❌ 无此输入角色 | ⚠️ 只能当普通参考图或 ControlNet 的 `Gray`/`Layout`/`Depth` 控制视频 | 官方没有"白模参考"概念（该能力是 Seedance 2.5 的官方卖点） |
| 姿态骨架图/视频 | ❌ | ✅ ControlNet-Union `Pose`（DWPose） | 需先生成骨架视频 |
| 深度图/视频 | ❌ | ✅ `Depth` | 单目深度序列 |
| 线稿/边缘 | ❌ | ✅ `Canny` / `HED` / `MLSD` / `Scribble` | MLSD 适合建筑/室内直线 |
| 分割图 | ❌ | ⚠️ 无原生 seg；`Layout`（色块框）是替代 | 布局控制需用 Wan2.1-VACE 的 layout 工具生成 |
| 法线图 | ❌ | ❌ 不支持（8 种条件里无法线） | 只能用于后期对照/提示词描述 |

`[官方][社区]`

### 3.2 参考视频

| 项 | 官方限制 | 实操建议 |
|---|---|---|
| 数量 | ≤3 段 | 一段只承担一个职责（运镜 / 动作 / 剪辑节奏 / 续写源） |
| 单段时长 | 2–15 秒 | 动作迁移取"完整一个动作循环" |
| 总时长 | ≤15 秒 | 3 段各 5s 就满了 |
| 格式/编码 | MP4/MOV；H.264/H.265；音频 AAC/MP3 | — |
| 单文件 | ≤50 MB | — |
| 分辨率 | 宽高 256–5760；比例 0.4–2.5 | 1080p 足够 |
| 帧率 | 23.976–60 fps | 参考视频按 24fps 语义处理 |

`[官方]`

内容要求（决定成败的软约束）：
- **用途必须单一且声明**：`<Video 1>` 只给运镜就写"只给运镜"，否则素材会把它的人、服装、场景、光线、声音一起带进结果；文本否定在 CFG=1 下压不住数据信号，必须写在 `retention_analysis` 里。`[社区]`
- **运镜参考最好拍"无人/无主体"的空镜或环绕静物**，从源头消除竞争。`[社区]`
- **动作参考**：只取一个可命名动作（如"走路节奏与手臂时序"），别把整段视频当"动作"。`[社区]`
- **Blender playblast 作为参考视频要慎用**：模型会倾向于把灰模的材质/打光也搬过来；若要用，必须限权为 `weak_reference` 并明确"不迁移材质与光照"，否则优先走 ControlNet 的 Depth/Pose 通道。`[推断]`
- **视频编辑/续写**：`<Video 1>` 作为编辑源时必须用 `[video editing]` 前缀 + 固定句 `The target video is an edited version of <Video 1>.`；原声保留要加 `audio reuse`。`[官方]`

### 3.3 参考音频

| 项 | 官方限制 | 实操建议 |
|---|---|---|
| 数量 | ≤3 段（独立音频） | 一条人声 + 一条音乐足够 |
| 单段时长 | 2–15 秒 | 音色参考 3–8 秒性价比最高 |
| 总时长 | ≤15 秒 | — |
| 格式 | WAV/MP3 | WAV 无损 |
| 单文件 | ≤15 MB | — |
| 必需搭配 | **不能作为唯一参考**，至少 1 图或 1 视频 | 官方 API 语义；ComfyUI 当前可单跑 ⚠️ |
| 采样 | 引擎内部 32kHz；其他采样率会被重采样 | 直接给 32kHz/44.1kHz WAV |

`[官方]`

**用途与写法对照：**

| 目标 | 关系词 | 提示词怎么写 |
|---|---|---|
| 1:1 用这段声音当最终音轨（歌声/台词/整段 BGM） | `fully_copy`（+ summary 前缀 `audio reuse`） | `<Audio 1>: fully_copy - <Audio 1> is reused 1:1 as the target video's complete final audio track.` |
| 只借音色/语气演新台词 | `reference`（+ `audio reference`） | `<Audio 1> is the voice-timbre reference for <Subject 1> (S1).` + `<Audio 1>: reference - follow timbre and delivery without copying the waveform.` |
| 只借 BGM 风格/节奏 | `reference` | 在 `non_diegetic_music` 里写"<Audio 2> 作为配乐风格参考" |
| 部分复用 | `partially_copy` | 说明复用哪一段/哪一音层，新加什么 |

`[官方]`

**关于对口型/演唱**：H3 是音视频联合生成，口型由"说话人 ID + `<d>` 台词 + 该镜头里的发声动作描述"共同驱动；**音色参考能提高音色一致性，但不保证逐字口型精确**。社区实测显示非英语口型误差明显大于英语，建议：一句一镜、每句 12–15 字以内、避免大特写（大特写会放大口型误差）、让说话人视线稍偏镜头。`[社区]`

### 3.4 组合上限与请求体

- 参考文件合计 **≤12 个**（9 图 + 3 视频 + 3 音频中任意组合，但总数不能超 12）。`[官方]`
- 请求体 **≤64 MB**；Base64 内联会膨胀约 33%，大素材一律用公网 URL 或 `mm_file://`。`[官方]`
- 首尾帧 + 参考素材不可同请求（见 1.5）。`[官方]`

### 3.5 首尾帧一致性与版权/肖像注意

- **首尾帧一致性**：I2VA/FL2VA 的图会被**精确锚定在 0.00s 与结束时刻**，因此两张图的**画幅比例、景别、主体朝向、光线**要接近；比例不一致时引擎会按"首帧拉伸 + 尾帧居中裁切"处理，可能造成画面位移。`[官方源码][推断]`
- **FL2VA 优先单镜头**；确实需要切镜时，尾帧必须由最后一个 `[Shot N]` 落到。`[官方]`
- **版权/肖像**：H3 本地权重为社区许可（排除美/欧/英/韩本地部署，年收入 >2000 万美元需授权，须标注模型名）；官方 API 对输入与增强提示做自动审核。真人参考素材需本人授权，声音克隆同理；成片按中国 AI 标识与欧盟 AI Act 第 50 条要求标注。`[官方][内部资料]`

| 模板 | 任务 | 用的 diffusion 权重 | 关键输入 |
|---|---|---|---|
| `video_minimax_h3_t2v` | T2VA | `minimax_h3_fl2va_pruned_int8_convrot` | prompt、宽高、时长 |
| `video_minimax_h3_i2v` | I2VA/FL2VA | 同上 | + `first_frame`、`last_frame`（可选） |

### 4.2 节点接法总表（"ComfyUI 里 H3 输入接什么"清单）

| 输入 | 上游节点 | 接到 H3 的哪个节点/接口 | 说明 |
|---|---|---|---|
| 文本提示词 | `PrimitiveStringMultiline`（或任意 STRING） | `MiniMaxH3ImageToVideo.prompt` / `MiniMaxH3ReferenceToVideo.prompt` | 单框内写完整三段/六段；支持 `embedding:minimaxh3_xxx` 风格 token |
| 首帧图 | `LoadImage` | `MiniMaxH3ImageToVideo.first_frame` | 精确锚定 0 帧（拉伸到画布） |
| 尾帧图 | `LoadImage` | `MiniMaxH3ImageToVideo.last_frame` | 锚定最后一帧（保持比例裁切） |
| 参考图 ×N | `LoadImage` ×N | `MiniMaxH3ReferenceToVideo.ref_images.ref_image_0…8` | 最多 9；编号=槽位顺序 |
| 参考视频 ×N | `LoadVideo` / VHS 视频加载 → IMAGE 帧序列 | `…ref_videos.ref_video_0…2` | 需 2–15s、24fps 帧序列；≥5 帧，自动裁到 17k+5 |
| 参考视频原声 | 视频加载节点的音频输出（或 `LoadAudio`） | `…ref_video_audios.ref_video_audio_0…2` | 与**同编号**视频配对；会占用 `<Audio j>` 标签 |

| 文本/图像编码器 | `CLIPLoader`（type=`minimax`）+ `VAELoader`（video）+ `VAELoader`（audio） | H3 节点的 `clip`/`vae`/`audio_vae` | 不接 VAE 时参考只进文本编码器，不进 DiT |
| 时长（秒→帧） | `PrimitiveFloat` + `ComfyMathExpression`：`max(5, round(a*24)) + (5-(max(5,round(a*24))%17))%17` | `length` | 自动吸附 17k+5 |
| 分辨率 | `ResolutionSelector`（16:9 + 0.98MP + 32 倍数） | `width`/`height` | 0.98MP=1344×768 为官方 768p |
| 结构控制视频 | `LoadVideo` → `MiniMaxH3FunControlNetApply.control_video` | 模型 patch 后进采样 | 支持 Canny/Depth/HED/MLSD/Pose/Scribble/Layout/Gray |
| 局部重绘 mask | `LoadImage`（黑白）→ `.mask` + 原视频 `.source_video` | 同上 | 白色=重画，黑色=保留 |
| 任意帧锚点 | `MiniMaxH3AddGuide`（可串联多个） | `positive` conditioning 链 | 图/短片/音频锚到任意 frame_idx，负值从结尾倒数 |
| 采样 | `KSamplerSelect(res_multistep)` + `BasicScheduler` + `BasicGuider` + `SamplerCustomAdvanced` | — | **无 negative**；`BasicScheduler.steps` 受 Turbo 开关控制 |
| 解码/封装 | `VAEDecode`（video VAE）+ `VAEDecodeAudio`（audio VAE）+ `CreateVideo(fps=24)` | — | 输出带同步音轨 MP4 |
| 风格 LoRA / Turbo | `LoraLoaderModelOnly` | — | Turbo LoRA 强度 1.0；步数见下表 |
| 二采/放大 | `MiniMaxH3LatentUpscaleWithModel` + 潜空间噪声 mask | — | 社区用"二采"补脸/补细节，但重采样过度会丢首帧锚定 |

### 4.3 采样参数（4 步 / 8 步 Turbo LoRA 与基线）

| 场景 | 权重 | 步数 | CFG | Sampler / Scheduler | Sigma shift | 分辨率 | 备注 |
|---|---|---|---|---|---|---|---|
| T2V / I2V / FL2V 基线 | `minimax_h3_fl2va_pruned_int8_convrot` | **20** | **1**（BasicGuider，无负向） | `res_multistep` / `simple` | video **12** / audio **3**（`MiniMaxH3SigmaShift` 默认） | 0.98MP→1344×768；可用 0.2–0.9MP 档 | 官方模板默认 |
| FL2V 8 步 Turbo | 同上 + `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16` | **8** | 1 | 同上 | 12 / 3 | 768p 档 | 模板 `turbo_steps=8`、`strength_model=1` |
| FL2V 4 步 Turbo（768p 专用） | 同上 + `minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16` | **4** | 1 | 同上 | 12 / 3 | 768p | Comfy-Org 提供；画质/动态有损 |
| R2V（Ref2VA）基线 | `minimax_h3_ref2va_pruned_int8_convrot` | **20** | 1 | `res_multistep` / **`beta` 或 `normal` 优于 `simple`** | 12 / 3 | 0.4–0.98MP | 参考密集时调度器影响明显 |
| R2V 4 步 Turbo | 同上 + `minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16` | **4** | 1 | 同上 | 12 / 3 | 768p | 官方 R2V 模板的 Lightning/Turbo 开关 |
| 社区常用档（RefMod/LoRA 对比） | 各 checkpoint + 8 步 Turbo | 8 | 1 | `euler` / `simple` | 12 / 3 | 1152×640、124 帧 | 4090 上 RefMod 提取约 3 秒 ⚠️ |

**要点**：`[官方][社区]`
- **CFG 恒为 1**：所有官方模板都没有 negative/CFG 节点；"步数越多≠质量越好"，20 步是 `res_multistep` 的基线，不是低步数。
- **Turbo LoRA 与步数必须成套**：8 步 LoRA 配 8 步、4 步 LoRA 配 4 步；混配会糊或崩。关闭 Turbo 时走 20 步基线。
- **分辨率档位表**（16:9，multiple=32）：0.2MP→608×352；0.4→864×480；0.6→1056×608；0.8→1216×672；0.9→1280×736；**0.98→1344×768（官方 768p）**。本地不要用 1.0MP（会到 1376×768，超 768×1344 面积上限）。
- **显存排序**：画质优先升量化档（int8→fp8 仅作退路；`int8_convrot` 需 cu130 的 PyTorch），而不是加步数；身份在参考模式下走文本编码器，编码器量化档直接影响像不像。

### 4.5 进阶：多关键帧、局部重绘、长视频

- **`MiniMaxH3AddGuide`**：可以把一张图、一段短片（自动裁到 5/22/39… 即 17k+5 帧）、一段音频（与视频同一时间轴）锚定在**任意像素帧**，`frame_idx` 可为负（从末尾倒数），可串联多个节点实现"多关键帧/分段控制"。这是本地做"分镜逐拍控制"的核心节点。`[官方源码]`
- **局部重绘/扩展**：官方称 ComfyUI 还暴露"latent noise masks for inpainting or extension"、prompt embeddings、Sage Attention 加速；这些随 ComfyUI 版本演进，生产工作流要锁版本。`[官方]`
- **结构控制**：`MiniMaxH3FunControlNetApply` 接受 `control_video` + 可选 `mask`/`source_video`；生成帧数向下吸附到最大可解码的 17n+5、时长 ≤15 秒、画布跟随控制视频比例、固定 24fps；`control_context_scale` 默认 1.0（最强），<1 减弱，0 关闭。`[官方源码][社区]`
- **Fun-ControlNet-Union 2.0 的条件集**：Canny、Depth、HED、MLSD、Pose（DWPose）、Scribble、Layout（Wan2.1-VACE 色块框）、Gray；控制分支注入 10/50 个 transformer block；guidance 蒸馏（`guidance_scale` 必须 1.0），示例 40 步；支持局部重绘（`control_in_dim=49`）。`[社区]`

## 5. 社区最佳实践

### 5.1 角色三视图/设定图怎么生成

- **生成工具**：本地用 FLUX.1 Schnell（Apache-2.0、4 步、低配可跑）或 FLUX.1 dev/Kontext；云端用 Nano Banana 2（Gemini 3.1 Flash Image）等图像模型做多角度/换装；上游图质量决定 H3 参考上限。`[官方][推断]`
- **生成规范**（为了 H3 好认）：中性纯色背景、无遮挡、无手势、无强投影；每个角度单独出图、同一角色同一 prompt 族；补 1 张面部特写 + 1 张手部特写 + 1 张全身；分辨率短边 ≥1024（H3 内部最多按 2048 处理）。
- **不要直接产出网格设定图**作为 H3 主参考（见 3.1）；网格图只作为"内部设定卡/分镜板"或 RefMod/LoRA 的训练底图。`[社区]`
- **两种进阶一致性方案**（社区实测，RTX 4090/48GB GPU）：
  - **RefMod**：用 ComfyUI-MiniMaxH3Mod 从一张角色设定图提取 RefMod（"Full Reference"，1024px，**约 3 秒**），之后 Ref2VA **不带图**、直接把 RefMod 应用到 conditioning。`[社区]`
  - **身份 LoRA**：19 图/500 步/lr 3e-4/rank 16 约 43–46 分钟，但"几乎没改变脸"；50 图/3000 步学到的是"类型"而非"这张脸"；第三次才接近。结论：**LoRA 不是低成本首选，先做 RefMod 与参考图基线**。`[社区]` ⚠️ 单一团队实测

### 5.2 跨镜头一致性：7 条可执行规则

1. **一个 `<Subject N>` 定义贯穿全片**，身份描述逐字复用（换词就是漂移源）。`[官方][社区]`
2. **参考图设 `ref_image_size=max`**（参考>1MP 时才有效；小图两档等价）；身份优先时编码器别用最低量化档。`[社区]`
3. **用独立高清图，不用网格图**；2–4 张覆盖"镜头实际会露出的角度"。`[社区]`
4. **减少竞争**：同一条请求里不要同时给"含真人的参考视频 + 高保真人像图"抢身份轴；运镜参考拍空镜/静物。`[社区]`
5. **不要强行生成素材里没有的视角**（如只给正面却要 180° 环绕）——模型会靠猜，脸必漂；要么补图，要么改机位。`[社区]`
6. **景别策略**：一致性最稳的是中景/中近景；大特写放大口型误差，远景/背影丢失身份细节；需要特写时单独出一镜。`[社区]`
7. **固定 seed 逐项调参**（`control_after_generate=fixed`），每次只改一个变量；跨镜头用同一 seed 做基线对照。`[社区]`

### 5.3 常见失败模式与规避（症状→原因→改法）

| 失败模式 | 主要原因 | 规避方法 |
|---|---|---|
| **脸漂移 / 两个脸来回切** | ①身份写成独立 `<Picture N>` 而非 `<Subject N>`；②两个素材抢身份轴；③用 I2VA 强推素材里没有的视角；④`ref_image_size=match` 且参考图 >1MP；⑤编码器量化过低 | 合并为一个 Subject 并写明各素材贡献；视频加 `weak_reference` 限权；补角度图或改机位；设 `max`；升编码器量化档 |
| **小细节（痣/疤/纹身/首饰）不出现** | 提示词没写；低对比/偏位小特征被"平均脸"抹平；宽景下物理像素不够 | 逐项写"位置+侧别+尺寸"的描述并在 `retention_analysis` 复述；该细节必须读出时用中近景；宽景别期待它出现 |
| **口型不齐 / 嘴型对不上** | 一句太长、语速密、大特写；非英语语种误差更大；画外音没声明闭嘴 | 一句一镜、≤12–15 字、避免大特写、视线略偏；画外音固定用 `says in an off-screen voiceover` + 明确"lips remain completely closed" |
| **手部畸形/多指** | 手全入画且强透视伸向镜头 | 裁掉（`hands passing just outside the top corners of the frame`）或正向写 `five clearly separated fingers, a firm grip` |
| **文字乱码/拼错** | 模型对画面文字是"生成图形"而非排版 | 少文字、短文字、引号内逐字给；多次重试；重要文字后期加 |
| **多主体混淆/服装串** | 素材职责未拆、一个人物由多图不同服装定义 | 每个主体独立 Subject；服装/配色逐项写；参考视频限权；必要时一次只训练/锚定一个主体 |
| **参考泄漏**（参考视频的服装/场景/光线被搬进结果） | 视频没有限权声明，CFG=1 下文本否定压不住 | 在 `retention_analysis` 写 `weak_reference` 并列出"不提供什么"；拍空镜参考 |
| **动作不执行/变成别的动作**（如"跳舞"） | 高频小动作词过多、真正主动作只出现一次；用散文式秒数描述节拍 | 把零碎动作降为一个从句；按"首先/接着/然后/最后"逐个面板列节拍；主 action 每段都单独一句 |
| **事件重复/不落地** | 扩散模型不会数数，"no second shot"反向加权；结局被平滑掉 | 只提一次、不写禁止；用"场景状态"封口（枪口放下、弹壳落地）；把中间姿态写出来并锁死终态 |
| **运镜变主体旋转** | 文本相机控制是最弱轴 | 用官方 `Arc Shot` 等词 + 幅度/速度；禁止身体转动要具体到部位；用视差描述（灯从右缘滑到左缘）证明相机动了 |
| **时长/节奏错位**（动作仓促/瞬移） | 写的动作时间线长于实际帧数（124 帧=5.17s）；`length` 向上吸附不提示 | 按帧表排时间线（124/141/158/175/192/209/226/243/260/277/294/311/328/345/362）；长运镜给 192–243 帧；超时拆镜 |
| **首尾帧不落地/二采后构图松** | FL2VA 写了多镜头、尾帧被强切；二采分辨率/重绘过度 | FL2VA 保持单镜头；尾帧由最后镜头落到；二采降重绘强度/分区域处理 ⚠️ |
| **输出软/噪** | 多为量化档或分辨率问题，不是步数 | 升量化档、降分辨率需求；参考密集时换 `beta`/`normal` 调度器做 A/B |
| **标签错位/参考不生效** | 编号按槽位而非文件名；换槽=重编号；视频原声抢先占 `<Audio 1>` | 提交前核对连线顺序与最终标签预览；音频单独参考在 ComfyUI 当前版本可跑（旧说法已过时） |
| **音乐/环境声乱配** | 漏写 `non_diegetic_music` 或 `overall_soundscape` | 两个字段都写；无配乐写 `N/A`；配乐只写乐器/速度/节奏/动态 |

`[官方][社区]`

### 5.4 素材组织方式：四张卡

建议把"往 H3 传什么"资产化，每个镜头导出成一个"输入包"（详见 7.2），内部用四类卡：

- **角色卡（Character Card）**：`id`、三视图/多角度单图路径、面部与手部特写、逐字身份描述（发型/发色/瞳色/服装/配饰/身形/口音与音色）、禁用项（"不含纹身"等）、`<Subject N>` 定义句、可选音色参考。
- **场景卡（Scene/Location Card）**：场景图（内含空间布局/光线/材质）、时间与天气、`<Subject N>` 环境定义句、可复用空镜参考视频（做运镜参考时优先用它）。
- **镜头卡（Shot Card）**：镜头编号、时长（帧数）、景别/焦段/机位/运镜（用官方词表）、首帧/尾帧图、参考视频、要传给 H3 的完整提示词、以及"参考职责表"（哪份素材负责哪一轴、保留强度）。
- **音频卡（Audio Card）**：对白/演唱/音效/BGM 分层、说话人 ID、语言、时长、是否 `fully_copy` 或 `reference`、采样率与文件路径。

**读表三条结论：**

1. **"传什么"的上限差异远大于"画质"差异**：Seedance 2.5（50 项）、Wan 3.0（20 项+文档）、Kling 4.0（15 项+10 关键帧）都比 H3 的 12 文件上限宽，但 H3 的**参考语义最严格**（标签 + 保留强度 + 任务前缀），复杂多主体项目里"写清楚"比"传得多"更能决定一致性。`[推断]`
2. **只有 Seedance 2.5 官方原生吃"白模"**；H3 要靠 ControlNet（Depth/Pose/MLSD/Gray/Layout）。如果用户链路的强需求是"Blender 灰模/预演直接当结构输入"，**H3 不是最优解，Seedance 2.5 才是**；H3 的优势在本地部署、音画同出与超严参考格式。`[推断]`
3. **Veo 3.1 的输入面在 2026 年已明显落后**（3 张参考图、8 秒、无音频输入），且 Gemini API 的 Veo 3.1 Preview 已于 **2026-10-22 关停**，迁移方向是 Gemini Omni 1.1 Flash 或 Vertex/企业平台的 GA 模型——引用 Veo 3.1 时务必核对这条时间线。`[官方]` ⚠️ 与"Veo 3.1 仍在售"的榜单口径并存，属渠道差异。

## 7. "Blender 预演 → H3" 的输入包设计

### 7.1 3D 预演产物分别能作为 H3 的哪类输入

| Blender 产物 | 能否进 H3 官方输入 | 作为哪类输入 | 具体做法与限制 |
|---|---|---|---|
| 灰模/白模单帧渲染 | ✅（当普通参考图） | Ref2VA `reference_image` 或 I2VA 首帧 | 只能作为构图/场景/比例参考；材质光照会被"照搬"或忽略，需在提示词里声明"渲染为写实/xx 风格" |
| 多机位渲染（同一镜头首/尾） | ✅ | **FL2VA 首帧+尾帧**（最推荐） | 一张首帧 + 一张尾帧精确锁构图；比例/景别/光线尽量一致；FL2VA 偏好单镜头 |
| 多关键帧渲染（中间姿态/调度） | ⚠️ 官方 API 不支持 | 本地 ComfyUI `MiniMaxH3AddGuide` 多锚点；或拆成多个短镜头 | API 只有首/尾两帧；≥3 个锚点必须本地 |
| 深度图/深度序列（Z pass） | ❌ 官方；✅ 本地 | ComfyUI ControlNet `Depth` 的 `control_video` | 需连续帧、24fps、≤15s；画布随控制视频比例 |
| 法线图/法线序列 | ❌ | ❌ 不能作为输入 | 8 种 ControlNet 条件里无法线；只能做后期对照 |
| 分割图 / 实例掩码 | ⚠️ 近似 | ComfyUI `Layout`（色块框，Wan2.1-VACE 流程）或 `mask`（局部重绘） | 无原生 seg 条件；可用 bbox 布局近似 |
| 姿态/动作（骨骼） | ❌ 官方；✅ 本地 | ControlNet `Pose`（DWPose）| 先把 Blender 骨骼渲染成骨架视频，或对实拍做 DWPose |
| 线稿/边缘 | ✅ 本地 | ControlNet `Canny` / `HED` / `MLSD` / `Scribble` | MLSD 适合建筑/室内直线；Canny 适合硬边 |
| 相机参数（焦段/位移/轨迹） | ❌ 无接口 | **只能写进提示词**（运镜词汇 + 幅度/速度 + 视差描述） | H3 不支持数值相机参数；轨迹可渲成参考视频走 Ref2VA 运镜参考 |
| 动作参考视频（playblast/动捕） | ⚠️ 受限 | Ref2VA `reference_video`（限权 `weak_reference`）或 ControlNet `Pose/Depth` | 灰模 playblast 会带灰模外观，必须声明"不迁移材质/光照"；更稳的是渲成骨架/深度 |
| 音频（口播/唱段/音效） | ✅ | Ref2VA `reference_audio`（音色/歌唱/节奏）或 `fully_copy` | 2–15s/段、总 ≤15s；独立音频需配视觉参考 |

**三条路线（按预算/精度选）：**

- **路线 A（快、纯 API）**：FL2VA 首尾帧 + 结构化提示词；适合构图已由 Blender 锁死的镜头。2K 用 `MiniMax-H3` + Regenerate-2K。
- **路线 B（一致性优先、纯 API）**：Ref2VA（2–4 张角色图 + 场景图 + 音色 + 限权运镜视频）；适合对白/演唱/多镜头。
- **路线 C（结构优先、本地）**：FL2VA 首尾帧（或 T2VA）+ Fun-ControlNet-Union 的 Depth/Pose/MLSD/Gray 控制视频；适合强运镜、复杂调度；输出 768p，需要 2K 再走 API 再生成。

### 7.3 镜头输入包 QC 标准（12 项）

1. 模式唯一：首尾帧 **或** 参考，不混；FL2VA 是否确实单镜头。
2. 素材数量在限内：图 ≤9、视频 ≤3、音频 ≤3、合计 ≤12。
3. 每段视频/音频 2–15s，各自总时长 ≤15s，单文件 ≤50MB / ≤15MB。
4. 图片 ≤30MB、边长 256–5760、比例 0.4–2.5；角色图短边 ≥1024。
5. 标签与连线/上传顺序**逐一对照**（编号按模态、按槽位，不按文件名）。
6. 每个素材都有"职责 + 保留强度 + 不提供什么"三件套。
7. 身份描述逐字一致（角色卡 → Subject 定义 → 每镜头描述）。
8. 时长按帧网格：107/124/…/362，且提示词时间线与帧数匹配（1s≈24 帧）。
9. 台词一句一镜、≤12–15 字；`<d>` 里只放语言标签+原话；画外音声明闭嘴。
10. 两个声音字段都写（`N/A` 也要写）；配乐只写乐器/速度/节奏/动态。
11. 全篇无否定句/无"不要"；负向改写成正向或场景状态。
12. **存档 `prompt_final.txt`**（含 Context-IR 之后的最终提示词）与所有素材哈希——2K 再生成必须原样重放。`[官方]`

## 8. 给"本地制作软件 → H3"链路的落地建议

1. **把"提示词"当工程产物而不是文案**：本地软件应输出**结构化的 H3 提示词**（三段式/六段式 + 标签 + 保留强度 + 任务前缀），并保存 Context-IR 后的最终版本；这是 2K 再生成与可复现性的前提。
2. **双轨出片**：需要精确构图/机位的镜头走 **FL2VA（Blender 首尾帧）**；需要对白/演唱/多主体一致的镜头走 **Ref2VA（角色卡+音色+限权运镜）**。两者不要在同一请求里混。
3. **本地先出 768p、批量筛片，只有选中的镜头才上 2K 再生成**：本地 H3-Base + Turbo LoRA 的边际成本最低，2K 再生成按秒计费，适合"少量精修"。
4. **需要结构硬控时，把 Blender 渲成"控制视频"而不是"参考视频"**：Depth/Pose/MLSD/Gray 序列走 ControlNet，避免灰模外观泄漏；运镜参考尽量用空镜。
5. **用 Seedance 2.5 做"白模预演"的 A/B**：同一镜头分别用 H3（ControlNet）与 Seedance 2.5（白模参考）跑，按"结构还原度 / 身份一致度 / 音画质量 / 成本"打分，再决定主力模型。`[推断]`
