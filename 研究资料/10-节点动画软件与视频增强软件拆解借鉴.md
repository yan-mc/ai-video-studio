## 0 结论先行

1. **视频增强软件 89 模型目录最值钱的不是模型，而是元数据 schema**："任务-后端-精度-分块-显存-依赖-推荐规则"七件套可直接转成我们的《后处理模型清单 v1》【观察｜T-00 §4、T-02 §3/§5/§8】。
2. **视频增强软件权重不可复用**：加密 `.tz` 从 `<视频增强软件权重域名>` 按需下载，配套 RLM+OAuth 许可；12GB 笔记本只能走开源替代【观察｜T-00 §3-§5】。
3. **视频增强软件三大工程做法值得照搬**：多后端工厂+CPU 兜底、tile 候选集与 `baseGB+pixelsPerGB` 显存估算、vaip 处理图 DAG（命名输出/帧缓存/处理器链）【观察｜T-05 §4/§6/§7】。
4. **视频增强软件 55 条编码器定义是"编码器能力矩阵"范本**：按平台/GPU/位深/alpha/容器/码率模板声明，运行时按硬件过滤【观察｜T-02 §8.3、T-04 §3.4】。
5. **节点动画软件的可借鉴核心是"声明式节点定义"**：491 节点=JSON 定义（nodeType/superType/attributes/triggers/ui）+386 个 C++ 类注册；节点自带 UI 布局、枚举、取值范围、输出触发规则【观察｜C-00 §4/§5、C-02 §3.1】。
6. **动效页不必自研引擎**：先做"模板+Lottie/FFmpeg 叠加"，中期用节点动画软件式节点 schema 描述 10—20 个图形/文字/信息图节点【推断】。
7. **节点动画软件的 MCP 模式几乎可原样搬成协议**：`read_preamble` 门闩、`search_docs/search_api/get_*` 检索、`preflight_*` 预检、`snapshot_layer` 视觉校验、`cleanup_workspace` 会话隔离——正是 DSH 动效页/后处理页需要的 Agent 工具形态【观察｜C-04 §8、MCP §1】。
8. **12GB RTX 4080 Laptop 结论**：可跑 SeedVR2-3B int8（约 8GB，含 block swap）、Real-ESRGAN、RIFE/FILM、MMAudio(6GB)；不建议 SeedVR2-7B 与 FlashVSR（官方仅 A100/A800 验证）；H3 768p 生成与后处理必须串行【推断，据 T-00 + 开源显存口径】。
9. **两份拆解的 QML/节点定义/模型目录均为商业软件资产**：只能参考结构与字段，不能随产品分发；自用插件合规，公开分发需全部重写【推断+许可提示】。
10. **最大不确定**：视频增强软件推荐规则仅 1 条（按目标高度）、tiling 选择算法/后端精确优先级/`.tz` 格式均为【未知】，不能当作规范直接实现。

## 1 视频增强软件 → 我们的"后处理模型选择器"

### 1.2 可直接复用的字段（我们的 manifest 设计）

| 我们的字段 | 对应视频增强软件字段 | 用途 | 复用方式 |
|---|---|---|---|
| `id/family/display_name` | shortName/displayName/gui | 模型唯一标识与分组 | 结构复用，值自填 |
| `task` | function/modelType | 超分/补帧/降噪/稳定/AutoShot | 直接沿用 9 类枚举 |
| `backends[]/precision` | backends/precision | 后端能力声明 | 收敛为 cuda/trt/cpu |
| `scales[]` | scales | 支持倍率（0.25–6） | 结构复用 |
| `blocks[]/overlap` | blocks/blockOverlap | 分块候选与融合重叠 | 直接照搬设计 |
| `vram_model` | baseGB/pixelsPerGB | 显存估算公式 | 直接照搬公式 |
| `deps[]` | dependencies | 依赖模型（自动参数等） | 结构复用 |
| `processors[]` | processors（up/aup/shot/slm…） | 处理链短名 | 改为我们的 `sr/interp/denoise/qc` |

| `recommend_rules` | target-resolution 规则 | 目标高度→模型 | 阈值复用，映射开源 |

【推断】按此 schema 落成 `post-models.json` + `presets.json` 两个文件，即可把"模型选择器"做成纯数据驱动，UI 与编排器不需要认识具体模型。

### 1.3 视频增强软件功能 → 开源替代（12GB 视角）

| 视频增强软件能力 | 开源替代 | 12GB 笔记本可行性 |
|---|---|---|

## 2 视频增强软件运行时/媒体管线 → ComfyUI/FFmpeg 适配器借鉴

| 设计点 | 视频增强软件做法【观察】 | 借鉴到我们 | 注意 |
|---|---|---|---|
| 多后端工厂 | `ModelBackendFactory`+`DeviceSelector`+`SystemInfo`；TRT→ONNX→OpenVINO→CPU 回退（T-05 §4.2） | 适配器暴露统一 `backend` 参数：cuda/trt/cpu，失败自动降级 | 视频增强软件精确优先级【未知】 |
| 显存/tile | `TileSplitter→TiledProcessorRunnerPool→TileMerger`；Gaussian/Linear blending；按 VRAM 选 block（T-05 §6.2） | 自建 tile planner：按 `baseGB+px/GB` 选块，块间重叠融合 | 块边界接缝是主要风险 |
| 处理图 DAG | `GraphProcessor` 拓扑排序、命名输出、`FrameCache`、`FilterStack`（T-05 §7） | `pipeline.json`：decode→sr→interp→color→encode，每步可缓存/断点续跑 | 我们用声明式管线替代 C++ 图 |
| 两条执行路径 | 应用内 in-process 编码 vs `ffmpeg.exe`+`tvai_up/fi/pe/stb/cpe` 滤镜（T-00 §5） | ComfyUI HTTP 主链 + FFmpeg CLI 兜底/批处理 | 两条路径都要有 ETA |
| 编码器矩阵 | 55 条/15 组：encoderName/pix_fmt/容器/alpha/位深/分辨率上限/码率模板/平台/GPU（T-02 §8.3） | 自建 `encoder-catalog.json`，按 GPU 过滤 NVENC/QSV/AMF | 不照抄数值，需实测 |
| 预览/代理 | `DiskCacheWriter` 编码预览缓存 + mpv A/B 分屏（T-04 §3.5-3.6） | 低码率代理 + 分屏对比 + 入出点 trim | 复用交互，不复用代码 |
| 色彩 | OCIO 2.3/2.5（ACES）、HDR Rec.2100-PQ（T-05 §7.4） | 单点 OCIO 管理，不做生成式 HDR | 12GB 下先放弃 HDR |
| 插件 | OFX 4/AE 2/Nuke 1 + MediaCore 共享运行时（T-04 §9） | 不做宿主插件；用中间格式（OTIO/EXR 序列）交换 | 工作量过大 |

### 3.2 不值得/不能复用

- **V8+Skia+FFmpeg 6.1.1 原生引擎**：自研成本极高，动效直接用 Remotion（代码视频）/Blender/FFmpeg 组合。
- **C++ 插件 ABI**（Api.dll 372 导出）与**加密脚本 `.jsc/.skslc`**：不可复用，也无必要。
- **491 节点全量**：只取片头/信息图子集；图表 C++ 实现细节（vfunc）本就【未知】（C-00 §10）。
- **Canva OAuth/AI Studio/配额**：依赖闭源云服务，不复用。

## 5 DSH 面板功能清单与 12GB 结论

| 页面 | P1（先做） | P2（下一步） | P3（有余力） |
|---|---|---|---|
| **后处理页** | 一键预设（清晰/修复/补帧/去噪）；目标分辨率+FPS；模型选择器（自动推荐+手动覆盖）；显存估算与 tile 提示；任务队列/重试；A/B 分屏对比；导出编码器选择 | 分镜批量、QC 报告（SSIM/LPIPS/PySceneDetect/口型）、音频响度与混音、字幕烧录、预览代理 | SR→补帧→色彩多级串联、LUT/OCIO、多卡/云 API 分流 |
| **动效页** | 片头/标题/字幕条模板 + Lottie/MP4 导出；文字动画预设；与镜头时间线叠加 | CSV→柱/饼/折线信息图三模板；转场模板；品牌色/字体包 | 节点动画软件式节点式程序化动效（10—20 节点子集）、表达式/数据绑定 |

**12GB 显存结论**：
- ✅ 可跑：SeedVR2-3B int8（约 8GB，block swap，目标 1440p 级）、Real-ESRGAN、RIFE/FILM、MMAudio(6GB)、HunyuanVideo-Foley XL offload(8GB)、IndexTTS(6GB)。
- ⚠️ 不建议：SeedVR2-7B、FlashVSR（官方仅在 A100/A800 优化，消费卡兼容未知）、4K 本地超分。
- ❌ 不能：视频增强软件模型（加密 `.tz`+RLM/OAuth 许可+私有运行时，无法移植）。
- 关键约束：H3 768p 生成与后处理不能同时驻留 12GB，必须**串行队列+模型卸载**；交付建议 1080p/1440p，4K 走云。

## 6 未解、风险与许可

- **许可**：节点动画软件/视频增强软件均为闭源商业软件，EULA 通常禁止逆向与再分发；本次拆解声明为互操作学习。**可做**：参考 schema/字段/交互后全部重写；**不可做**：拷贝 QML/JS/节点定义/预设/模型目录原文随产品分发、绕过 `.tz` 加密或 RLM/OAuth、复用其商标与 MCP 工具名（建议改名）。
- **风险**：视频增强软件的后端优先级/tiling 选择算法/`preflight/postflight` 语义/`.tz` 结构均为【未知】；节点动画软件的 Chart 运行时、MCP JSON Schema、`.cvx` 加密亦为【未知】；两软件版本迭代快，schema 需锚定版本（节点动画软件 2.8.0 构建 2026-09-29；视频增强软件 1.7.2）。
- **待实测**：12GB 下「SR+补帧+音频模型」的并发/串行耗时与温度；RIFE vs FILM 在 24→60fps 的伪影差异；SeedVR2-3B int8 在 1440p 的接缝与耗时；开源替代相对视频增强软件的画质差距（建议建 10 镜头 A/B 集）。
